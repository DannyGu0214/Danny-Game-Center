## 2. 크기·속도 단일화

원본은 `eco/atoll/data.js`예요. 화면은 `G.bodyLen(sp)`(= `len × SIZES[등급].draw`)에 개체차(±12%)만 곱하고, 속도는 규칙이 써요. 주소 옵션 `?sizes=`는 등급 배율 덮어쓰기로 남겼어요.

| 종 | 규칙(P1) | 시제품(P1) | **고른 값** | 이유 |
|---|---|---|---|---|
| 해삼 | 0.6 | 0.55 | **0.6** | 0.55면 균형감 테스트의 "칸두 바닥 몫 ≥ 넓이 몫의 절반"에 걸려요. 임시 격자 0.11 / 기준 0.115, 실제 지형 0.07~0.08 / 기준 0.085 [확인] |
| 소라게 | 1.5 | 1.15 | 1.15 | 시제품 생동감 값 |
| 몰디브흰동가리 | 1.2 | 1.9 | 1.9 | 〃 |
| 문어 | 1.2 | 1.0 | 1.0 | 〃 |
| 보름달물해파리 | 0.45 | 0.36 | 0.36 | 〃(결산 로그의 예) |
| 바다거북 | 1.5 | 1.45 | 1.45 | 〃 |
| 쥐가오리 | 1.8 | 1.75 | 1.75 | 〃 |

- 크기 배율(S 1.35 · M 1.1 · L 0.95 · XL 0.85)과 몸 길이 `len`은 두 곳 값이 같았어요. 데이터 쪽만 남겼어요.
- 시제품은 개체마다 속도에 0.8~1.2를 곱하고 방향을 돌리는 동안 느려졌어요. 규칙은 길을 따라 정해진 속도로 가요. 그래서 같은 숫자여도 화면에서는 규칙 쪽이 조금 빨라 보일 수 있어요 [추정].
- 수치를 바꾼 뒤 봇 T8 도달 시간은 거의 같았어요(6절). 경제는 움직임에 기대지 않아서 방치 플레이 값은 220분 그대로예요 [확인].

## 3. 확장 영역과 지형(발견하고 고친 것)

- **발견** [확인]: `eco/atoll/terrain.js`의 `kindAt`·`cellHeight`·`heightAt`은 세 번째 인자 `opts.ext`가 없으면 **확장 영역 칸을 '블록 밖'으로** 답해요. 규칙은 `opts` 없이 불렀어요. 그래서 1차 사이클에서 실제 지형으로 돌린 봇(T8 88.9분)에는 확장 영역 칸이 아예 없었어요. 한도는 T8에 44마리로 늘지만 모두 본 블록 안에 들어갔고, 확장 영역 꾸미기 항목도 채울 수 없었을 거예요 [추정].
- 지형 함수는 열렸는지에 따라 **본 블록 +x 가장자리 3칸 띠(x = 37~39)**도 달라져요. 닫혀 있으면 바깥 비탈이고, 열리면 이어진 바다예요 [확인: 테스트].
- **고친 방식**: `eco/atoll/data.js`의 `atollTerrain(terrain, ext)`가 열리기 전·후 지형 약속을 따로 만들어요. 규칙 상태 S는 지형과 무관한 순수 데이터라서 같은 S를 열린 지형의 규칙으로 불러오면 이어져요(`fitTerrain`이 옮기거나 돌려준 것 0개) [확인: `test/terrain.test.js`].
  - 화면: 저장된 게임이 T8이면 열린 지형으로 시작해요. 게임 중에 T8이 되면 "확장 영역이 열렸어요" 창 → [지금 넓히기] → 저장하고 다시 불러와요. 지형·물·카메라·안개 상자를 한 번에 다시 만드는 가장 단순한 길이라 골랐어요. 끊김 없이 옆으로 넓어지는 연출은 아니에요.
  - 봇: `loadSim`이 실제 지형(모듈에 `bounds`가 있음)이면 두 규칙을 만들고, T8에 바꿔 이어 가요.
- 지형 재설계(칸두 끝 절벽 등)는 하지 않았어요.

## 5. 공개 함수·상태 모양

### 5.1 규칙(`sim/rules.js`)에서 더한 것

P1 보고서 2·3절 그대로이고 아래만 더했어요. 화면에 넘기는 상태 모양(`view(S)`)은 바뀌지 않았어요.

| 함수 | 돌려주는 것 |
|---|---|
| `creatures(S)` | `view(S).creatures`와 같은 배열(`{ uid, sp, x, y, z, face, pitch, st, ph, on }`). 화면은 매 단계 이것만 읽어요 |
| `props(S)` | `view(S).props`와 같은 배열(`{ uid, id, x, y, w, h, zone, layer, z, rot }`). 놓기·치우기·지형 맞추기 사건 때만 읽어요 |
| `limitWhy(S, id)` | 상한에 걸리면 안내 문장, 아니면 null |
| `zoneCount(S, zone)` | 그 구역 물건 수 |

`freeSpot`은 상한에 걸리면 null이에요(요청 후보·봇·화면의 권하는 자리가 함께 따라요). 지형 맞추기(`fitTerrain`)는 상한을 보지 않아요(이미 산 물건을 옮기는 일이라서).

### 5.2 데이터(`eco/atoll/data.js`)

```js
import { makeEco, atollTerrain, LIMITS } from './eco/atoll/data.js';
import * as TER from './eco/atoll/terrain.js';
const G = createSim(makeEco(atollTerrain(TER, ext)));            // ext: 확장 영역이 열린 지형인가
const G2 = createSim(makeEco(atollTerrain(TER, true), { limits: { water: 60 } }));   // 상한 시험
```

- `SPECIES[id].icon`, `ITEMS[id].icon`: 화면 목록용 그림 글자(규칙은 안 씀).
- `atollTerrain`은 `{ GRID, EXT, SEA_LEVEL, MAX_DEPTH, kindAt, cellHeight, heightAt, extOpen }`. 화면도 이 `heightAt`을 써서 규칙과 같은 지형을 그려요.


- 프롤로그는 동적 import로 불러요. 파일이 없으면 콘솔에 404가 한 줄 남고 건너뛰어요 [확인].

## 7. 화면 확인 [확인]

| 항목 | 결과 |
|---|---|
| 콘솔 | 오류 없음(프롤로그 파일이 없을 때 404 한 줄만) |
| 드로우콜·삼각형(견본 장면, 생물 44마리 · 물건 21개, 녹화 모드 1440×900) | 19회 / 222,630개(P1 19회 / 226,074개) |

| 규칙 단계 비용(44마리 · 물건 56개) | 단계당 약 0.005ms · 생물 그리기 갱신 약 0.04ms/프레임 |

| 줄 세우기 `?lineup=1` | 8종이 한 줄로(규칙 없이 고정) |

조작 확인 방법(정직하게)
- 내장 브라우저(실제 마우스 클릭): 타이틀 → 새 게임, 해삼 들이기, 놓기 모드에서 블록을 눌러 자리 옮기기, 새로고침 뒤 이어하기.
- 내장 브라우저 창이 앱에서 숨겨져 있어서 페이지가 뒤로 밀린 상태로 돌았어요. 그래서 화면 갱신이 멈췄어요. 나머지는 **임시 프로필로 띄운 headless Chrome**(대니님 Chrome과 별개)에서 확인했어요. 패널 단추는 요소 클릭으로, 캔버스·타이틀 누르기는 화면 좌표에 맞춰 **포인터 이벤트를 보내는 방식**으로 했어요. 진짜 마우스·터치 손맛(끌기와 탭의 구분, 터치 28px)은 대니님 노트북에서 봐야 해요.
- T8까지 가는 장면은 규칙 함수로 점수를 넉넉히 넣어 빨리 지나갔어요(열림 창 → 다시 불러오기 → 확장 영역에 놓기만 화면에서 확인).
- 프롤로그 자리는 프롤로그 세션의 지금 파일(`ui/prologue*.js·css`)을 잠깐 복사해 타이틀 → 프롤로그 → [건너뛰기] → 게임 순서를 확인하고 지웠어요(커밋에 없음). 확인 중에 한 번, 브라우저가 먼저 받은 404를 기억해 프롤로그 없이 넘어간 적이 있어요. 개발 중에만 생기는 일로 봐요 [추정].
- `tools/capture.mjs`(Playwright 필요)는 이 맥북에 Playwright가 없어 돌리지 못했어요. 같은 녹화 모드 손잡이(`__cap`)를 headless Chrome에서 직접 불러 그림을 찍었어요. 녹화 모드 쪽 약속(`__cap.ready`·`step`·`setView`·`snapshot`·`dump`·`info`)은 그대로라 원격 환경에서 그대로 돌 거예요 [추정].

## 10. 대니님 판단 필요

1. **물건 개수 상한**: 6.2절 표를 보고 켤지, 켠다면 어느 구역에 얼마나 둘지. 켠다면 확장 영역 몫을 따로 둘지도 함께요. 지금은 꺼져 있어요.
2. **"먹으러 가기"**: 없앤 그대로예요. 물건을 놓아도 생물이 모여들지 않아요. 놓은 직후 잠깐 모이는 화면 연출만 넣는 방법도 있어요(규칙 분포와 무관) [추정].
3. **해삼 속도**: 시제품 0.55 대신 0.6을 남겼어요(2절).
4. **확장 영역 열림**: 다시 불러오기로 넓히는 방식이라도 괜찮은지, 이어서 넓어지는 연출이 필요한지.
5. **조작감**: 노트북에서 직접 해 볼 것. 블록 위 끌기는 출렁임이고 빈 곳 끌기는 돌리기예요. 놓기 중에는 블록 누르기가 자리 옮기기예요.
