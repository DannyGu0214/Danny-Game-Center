### 0.2 새로 만들 기법

| 기법 | 권고 |
|---|---|
| 생물 몸의 젤리 변형 | **InstancedMesh + 절차적 꼭짓점 셰이더 변형**(인스턴스별 위상·속도 속성). 스키닝·모프는 쓰지 않아요. r187에서 해파리 200개 박동이 드로우 1회로 그려지는 걸 확인했어요 [실험] |

| 빛줄기·부유 입자 | 가산 혼합 판 메시 몇 장(빛줄기) + GPU에서 순환하는 Points 1회(부유 입자) [추정] |
| 몰디브형 MVP(3.3) | 섬과 해저를 **높이 함수 하나**로 만들고, 셰이더가 프래그먼트마다 수위와 비교해 물 위·아래를 나눠요. 수면 경계는 환경맵 반사 + 프레넬 + 굴절 흉내로 처리하고, 평면 반사·진짜 굴절은 보류해요. 카메라는 블록 밖에서 내려다보기↔측면을 연속으로 오가요 |
| 생태계 교체(3.4) | 물빛·탁도·조명을 `WaterProfile`·`EnvProfile` uniform 묶음으로만 바꿔요. 온대·한대·아마존 민물도 같은 셰이더로 돼요 |
| 공용 기반 분리(2.7) | `core/`(카메라·젤리 블록·지형·재질·인스턴싱·이름표)와 `aqua/`(물 시뮬·커스틱·헤엄 변형)를 나눠, Animal World 차기 버전이 core를 그대로 써요 |
| 드로우콜 예산 | 사례 1,289회 = 그림자 416 + 투과 패스 432 + 본 화면 441 [실험]. 우리 목표는 **프레임당 총 300회 이하, 본 화면 150회 이하, 투과 패스 0회** [추정] |

### 0.3 렌더러·버전 권고

- **three `0.187.0`(npm 최신, 2026-10-30 배포) + `WebGLRenderer`**를 권해요.
- 근거: 사례의 핵심 기법이 모두 `onBeforeCompile`인데, `WebGPURenderer`는 이것과 `ShaderMaterial`을 지원하지 않아요 [문서]. 이 환경에는 WebGPU가 없어 WebGPU 경로를 검증할 수도 없어요 [실험]. 사례를 r187로 그대로 돌려 보니 경고 2개뿐이고 드로우콜도 같았어요 [실험].
- vendor 방식: `three.module.js`와 `three.core.js` **두 파일**이 필요해요(r171부터 나뉨). r186.1부터는 npm 패키지에 `.min.js`가 없어요 [확인]. 합계 약 2.1MB(gzip 약 420KB)예요.
- 셰이더 주입 코드는 한 모듈에 모아 두면, 나중에 TSL로 옮길 때 고칠 곳이 한곳으로 줄어요 [추정].

## 2. 참고 사례의 기법별 명세

### 2.1 젤리 블록 출렁임

**동작 원리** [확인]

- 지형·물·소품·생물을 모두 담은 `world` 그룹 하나가 있어요. `matrixAutoUpdate`를 끄고 매 프레임 행렬을 직접 써요. 셰이더 변형이 아니라 **행렬 하나**로 블록 전체를 일그러뜨려요.
- 상태는 세 축이에요. 앞뒤·좌우 전단 `sx, sz`(위쪽이 옆으로 밀림)와 눌림 `sq`(위아래로 납작해짐)예요. 축마다 위치·속도·목표값이 있어요.
- 스프링 적분(반암시적 오일러):

```
for 축 in (sx, sz, sq):
    v += (-k * (x - target) - c * v) * dt
    x += v * dt
```

- 강성 `k`와 감쇠 `c`는 UI "탱탱함" 슬라이더에 비례해요. 강성은 대략 수십~수백 범위이고, 눌림 축은 전단보다 조금 더 단단해요.
- 행렬은 **블록 밑면(y = BOTTOM)을 고정점**으로 해요.

```
x' = (1 - q/2)·x + sx·(y - BOTTOM)
y' = BOTTOM + (1 + q)·(y - BOTTOM)
z' = (1 - q/2)·z + sz·(y - BOTTOM)
```

  위로 늘어나면(q>0) 옆으로 줄어요. (1+q)(1−q/2)² ≈ 1 − (3/4)q²이므로 **부피가 1차 근사로 보존돼요.** 이게 "젤리처럼" 보이는 핵심이에요.
- 입력 반응:
  - 땅이나 단면을 누르면 눌림 목표를 살짝 음수로 바꿔요(꾹 눌림).
  - 드래그하면 화면 이동량(dx, dy)을 카메라의 오른쪽·앞쪽 벡터를 수평면에 투영한 방향으로 바꿔 전단 목표 `tx, tz`로 써요(작은 값으로 클램프).
  - 놓으면 목표가 0으로 돌아가고, 스프링이 넘치며 출렁여요.
  - 버튼(뱃고동·맛 바꾸기)은 눌림 속도에 충격량만 더해요(`poke`).
- **물과의 결합**: 매 프레임 전단 속도의 변화량(= 가속도×dt)을 물에 넘겨요. 물은 수면 전체에 선형 기울기 `h -= ax·x + az·z`를 더해요. 블록이 한쪽으로 가속하면 물이 반대쪽으로 쏠려 파도가 생겨요.
- 그림자 받는 바닥(`ShadowMaterial` 평면)은 월드 밖에 있어서, 기울어진 블록의 그림자가 자연스럽게 따라 기울어요.
- HTML 제목 글자도 한 글자씩 span으로 쪼개고, 넘침이 있는 cubic-bezier CSS 키프레임으로 출렁여요. 3D와 UI가 같은 "젤리 언어"를 써요.

**조절 변수**: 강성 k, 감쇠 c, 눌림/전단 강성 비, 드래그 감도·클램프, 물 결합 계수.

**비용**: CPU는 스칼라 몇 개라 무시할 수 있어요. GPU는 0이에요(행렬 1개). 단, 월드 행렬이 일그러져 있으니 **레이캐스트할 때 월드 역행렬을 적용해야 해요.** 사례도 수면 좌표를 구할 때 광선을 월드 로컬 공간으로 옮겨요 [확인].

**우리 적용** [추정]

- 생태계 블록이 여러 개면 블록마다 독립 스프링을 둬요. 한 화면에 블록 하나만 보이는 구조라면 하나로 충분해요.
- 스프링 가속도를 ① 물 높이장, ② 생물 군집(관성의 반대 방향 힘), ③ 해초·촉수 셰이더의 "해류" uniform에 함께 넘겨요. 블록을 흔들면 물속 생태계 전체가 한 몸처럼 출렁여요. 사례보다 한 단계 나아간 연출이에요.
- 강성 상한에서 ω = √k ≈ 16, dt = 1/30이면 ω·dt ≈ 0.55예요. 반암시적 오일러는 안정해요. 다만 탭 전환 뒤 큰 dt를 막으려고 사례처럼 dt를 1/30으로 자르거나, 고정 1/60 서브스텝을 권해요.

### 2.2 젤리처럼 보이게 하는 재질과 조명

**렌더러 설정** [확인]

- 안티에일리어싱 켬, 픽셀비 최대 2, 톤매핑 `NeutralToneMapping`(노출 1), 그림자 `PCFSoftShadowMap`(r187에서는 제거되어 PCF로 대체돼요, 4절), `localClippingEnabled` 켬.
- 클리핑: 배 재질에 블록 4면 클리핑 평면을 줘서, 블록 밖으로 나간 배가 단면에서 잘려 보여요. 디오라마의 "잘린 세계" 느낌을 유지해요.

**환경과 빛** [확인]

- `RoomEnvironment`를 PMREM으로 구워 `scene.environment`로 써요. 세기는 낮춰 둬요(0.5 안팎). **이미지 파일 없이 반사광을 얻는 장치**이고, 젤리의 반짝임은 대부분 여기서 나와요.
- 반구광(위는 따뜻한 흰색, 아래는 베이지)과 태양 방향광 1개(그림자 2048², 정사영 그림자 범위를 블록에 딱 맞춤, bias·normalBias 조정)를 써요.
- 배경은 단색(따뜻한 회백색)이에요. 아주 옅은 `ShadowMaterial` 바닥이 그림자만 보여 줘요. 장난감을 탁자에 올려 둔 느낌이에요.

**물(젤리) 재질** [확인]

- `MeshPhysicalMaterial`, 투과 최대(`transmission` 1), 두께 2 안팎, 거칠기 거의 0, ior 1.33, 진한 파란 `attenuationColor`와 블록 크기보다 짧은 `attenuationDistance`, 클리어코트 최대(거칠기 거의 0), 정반사 강도와 환경맵 세기를 1보다 키움, 같은 계열 파란 자체발광을 약하게 넣었어요.
- "젤리 맛" 버튼은 이 재질의 흡수색·기본색·발광색과 지형 셰이더의 물색 uniform을 한꺼번에 바꿔요.
- 정리하면 젤리 = **투명 + 두께에 따른 색 흡수 + 아주 매끈한 클리어코트 정반사 + 약한 자체발광**이에요. 자체발광이 있어서 그림자 쪽도 어둡게 죽지 않고 "속이 빛나는" 느낌이 나요.

**투과의 실제 동작** [확인: three r187 소스, `renderTransmissionPass`·`transmission_pars_fragment`]

- 투과 물체가 하나라도 있으면, 매 프레임 **불투명 물체 전체를 별도 렌더 타깃에 한 번 더 그려요.** 이 타깃은 MSAA 4샘플 이상, half-float, 밉맵이 있어요. 그다음 투과 물체가 그 텍스처를 화면 좌표로 굴절 오프셋해서 읽어요. 진짜 광선 추적이 아니라 **화면 공간 흉내**예요.
- 흡수 거리는 실제 기하 두께가 아니라 `thickness × 모델 스케일`로 고정이에요. 투과율 = exp(−(−log(attColor)/attDist) × 그 길이)예요. 그래서 깊든 얕든 **물 색이 거의 균일해요.**
- 그 렌더 타깃에는 불투명 물체와 **양면(DoubleSide) 투과 물체의 뒷면만** 들어가요. `transparent: true` 물체는 들어가지 않아요.
- r176부터 `renderer.transmissionResolutionScale`로 이 타깃 해상도를 낮출 수 있어요(r170에는 없음) [확인].

**실험** [실험] (r187, 투과 물 박스 안에 해파리 200개와 불투명 구 30개)

| 해파리 재질 | 물 박스 밖에서 본 결과 |
|---|---|
| 투과(양면) | 보여요. 다만 분홍이 사라지고 남색으로 보여요 |
| `transparent` + opacity | **전혀 안 보여요** |
| (물 박스 없음) | 분홍·빨강 그대로 보여요 |

불투명 주황 구도 물 박스 너머에서는 짙은 청록으로 보였어요. 사례 측면 스크린샷의 물고기 색 변화와 같은 현상이에요.

**지형·소품 재질** [확인]

- 대부분 `MeshStandardMaterial`, 거칠기 0.6~0.95, 지형은 꼭짓점 색이에요.
- 나무·바위는 저다각형 정이십면체·정십이면체에 `flatShading`을 써서 장난감 느낌을 내요.
- 재질은 색+옵션 문자열을 키로 캐시해서 공유하지만, 그래도 89개예요. 지오메트리는 대부분 공유하지 않아요(상자 하나마다 새 BoxGeometry).

**우리 적용** [추정]

- 환경맵·반구광·방향광·톤매핑 구성은 그대로 가져와요. 생태계별로 반구광 색과 배경색만 바꿔요(극지는 차가운 흰색, 심해는 어두운 남색).
- 물 덩어리에는 투과를 쓰지 않아요(3.2절). 젤리 광택은 앞면 광택층(클리어코트 + 환경맵 + 프레넬 불투명도)으로 살려요.
- 투과는 꼭 필요한 "주인공 오브젝트" 한두 개에만 써요. 그때는 `transmissionResolutionScale`을 0.5쯤으로 낮춰요.

### 2.3 물

#### 2.3.1 높이장 시뮬레이션 [확인]

- 격자: 블록 수면을 131×91 칸(칸 간격 약 0.2)으로 나눠요. 칸마다 높이 h, 속도 v, 거품 f가 있어요. 시작할 때 지형 높이 표본 tH도 구해 둬요.
- 마스크: `wall`은 지형이 수위보다 높은 칸(육지)이에요. `shore`는 육지와 맞닿은 물 칸이에요. 수위(물때 슬라이더)가 바뀔 때만 다시 계산해요.
- 한 스텝:

```
kk = c² · dt / dx²
for 각 물 칸 i:
    이웃 4칸(육지·격자 밖이면 자기 값으로 대체 → 반사 경계)
    v[i] = (v[i] + kk · (l + r + u + d - 4·h[i])) · (1 - damp·dt)
for 각 물 칸 i:
    h[i] = clamp(h[i] + v[i]·dt, -상한, +상한)
```

- 프레임당 dt/2로 **두 번** 돌려요. 파속 c는 "탱탱함", 감쇠는 "파도 잔잔함" 슬라이더에 연결돼요. 안정 조건 c·dt/dx ≤ 1/√2를 넉넉히 만족해요(약 0.24).
- 교란 함수 `disturb(x, z, r, amt, foam)`: 반경 2r 창 안의 칸에 가우스 `amt·exp(-d²/r²)`를 더하고 거품도 더해요. 이 함수 하나로 드래그 휘젓기, 배의 항적, 구명튜브 착수, 먹이 투하, 물보라 낙하를 모두 처리해요.
- 그 밖의 쓰기 경로: 블록 흔들림용 전역 기울기(`slosh`), 바람 세기에 비례한 무작위 칸 미세 충격이 있어요.
- 드래그 휘젓기는 이전 점과 현재 점 사이를 일정 간격으로 나눠 교란을 여러 번 넣어요. 빠르게 그어도 끊기지 않아요.

**비용**: 약 1.2만 칸 × 2 스텝 + 메시 갱신(꼭짓점 1.2만 개 높이 쓰기 + `computeVertexNormals` 매 프레임) + 물 벽 4면 갱신이에요. 모두 CPU 단일 스레드예요. 노트북에서는 감당할 만하지만 매 프레임 법선 재계산이 가장 큰 몫으로 보여요 [추정].

#### 2.3.2 수면 메시와 재질 [확인]

- 수면 높이 = 수위 + h + "주변 물결"(사인 3개 합, 진폭은 바람에 비례, 얕은 곳에서 줄어듦)이에요. 육지 칸은 지형 아래로 내려 숨겨요.
- 거품은 같은 격자의 메시를 하나 더 만들어 수면 살짝 위에 띄우고, 꼭짓점 알파로 표시해요. 해안 칸은 늘 은은하게 깜빡여요.
- 잔물결 하이라이트: 프래그먼트 셰이더에서 방향·파장·속도가 다른 코사인 5개를 더하고, **해석적 기울기(미분)**로 법선만 흔들어요. 지오메트리 없이 반짝임이 생겨요.
- 수면 자체에도 커스틱 그물 무늬를 자체발광으로 더해요. 위에서 보면 "빛나는 그물" 질감이에요.

#### 2.3.3 물 벽(옆면) [확인]

- 블록 4면마다 띠 메시가 있어요. 꼭짓점 쌍의 아래는 지형 높이, 위는 그 가장자리 칸의 물 높이예요. **매 프레임 위쪽 꼭짓점을 갱신해서 벽 윗선이 파도를 따라 출렁여요.**
- 꼭짓점 속성(아래 0 → 위 1)으로 자체발광에 세로 그라데이션을 줘요(아래는 어둡고 위로 갈수록 밝음). 맨 위 좁은 띠는 하얗게 칠해 **수면선**을 그려요.
- 지층과 겹쳐 깜빡이지 않게 벽을 안쪽으로 아주 조금 들여요.

#### 2.3.4 커스틱 [확인]

- GLSL 함수 하나예요. 좌표를 사인·코사인으로 여러 번 되먹임 변형하고 거리의 역수를 누적한 뒤 거듭제곱으로 날카롭게 만들어요. Shadertoy의 널리 알려진 "Tileable Water Caustic" 계열 패턴으로 보여요(출처는 [추정]).
- 지형 재질 주입 내용(의사코드):

```
depth = 수위 - 이 프래그먼트의 로컬 y
if depth > 0:
    물색 = mix(얕은색, 깊은색, smoothstep(얕음, 깊음, depth))
    바탕색 = mix(바탕색, 물색, 깊이에 비례하되 상한 있음)
    cs = caustic(xz·s1, t·w1) + 0.6·caustic(xz·s2 + 오프셋, t·w2)   ← 두 겹
    자체발광 += 바탕색을 조금 밝힌 색 · cs · (얕은 곳에서 켜지고 깊을수록 지수 감쇠)
```

- 비용: 물속 지형 프래그먼트마다 반복 4회짜리 함수를 2번 불러요. 화면 일부만 덮어서 가벼운 편이에요.

#### 2.3.5 물보라 [확인]

- 900개짜리 링 버퍼 `Points`예요. 위치·속도·수명을 CPU에서 적분하고(중력, 수명 감소), 수면 아래로 떨어지면 죽어요. 가끔 그 자리에 작은 교란을 넣어 "떨어진 물방울 파문"을 만들어요.
- 매 프레임 전체 칸에서 무작위로 수십 칸을 뽑아, 그중 해안 칸의 속도가 문턱을 넘으면 물보라를 뿜어요(해안 부서짐).
- 점 셰이더: 화면 크기 = uScale × (수명 보정) / 시야 깊이예요. uScale은 창 높이·픽셀비·시야각으로 리사이즈 때 다시 계산해요. 프래그먼트는 원 밖을 버리고 가장자리를 부드럽게 해요. `transparent`, `depthWrite` 끔, `renderOrder`로 뒤에 그려요.

**우리 적용** [추정]

- 물속 시점이 주인공이라 수면은 "위에서 내려다볼 때의 뚜껑"이에요. 격자는 사례 수준이나 그보다 낮게(예: 칸 간격 0.25~0.3) 잡아도 돼요.
- 법선 재계산 대신 셰이더에서 h의 이웃 차분으로 법선을 구하면 CPU가 줄어요. 그러려면 h를 데이터 텍스처로 올려야 해요. 다만 지금 규모에서는 사례 방식도 충분해요.
- 물보라 셰이더는 부유 입자에 다시 써요(3.2.4).

### 2.4 지형과 지층 단면

**높이 함수** [확인]

- 값 노이즈(sin-fract 해시 + smoothstep 보간)를 3옥타브 fbm으로 써요.
- 바닥 = 기본 해저 높이 + 앞뒤 기울기 + fbm 요철이에요.
- 섬·반도·방파제는 2D SDF(원, 캡슐, 둥근 상자, 반평면)로 정의해요. 각각 `mix(해저, 섬높이, smoothstep(경계 띠, sdf))`를 구해 **max로 합쳐요.** SDF 차집합(`max(a, -b)`)으로 도크를 파내요.
- 같은 함수가 지형 메시, 물 격자의 지형 표본, 소품 배치(높이·경사 질의), 단면 위쪽 선에 모두 쓰여요. **단일 진실 공급원**이에요.

**지형 메시** [확인]

- PlaneGeometry 약 208×144 분할(꼭짓점 약 3만 개)의 y를 높이 함수로 정해요. 꼭짓점 색은 높이·경사·영역 SDF로 규칙 기반으로 골라요(모래, 해초 얼룩, 자갈, 콘크리트, 풀, 숲 등).

**지층 단면** [확인]

- 블록 4면에 바닥(BOTTOM)부터 그 가장자리 지형 높이까지 띠 메시를 세워요.
- 셰이더가 바탕색을 통째로 바꿔요. 로컬 y에 작은 사인 흔들림을 더한 값에 `step`을 여러 번 걸어 층 색을 쌓아요. 셀 해시로 알갱이 얼룩을 넣어요. 감마를 보정해요. **맨 위 얇은 띠는 위쪽 꼭짓점 색(풀·모래)으로 칠해서** 지표가 단면 위로 살짝 덮이는 느낌을 내요.
- 밑면은 단색 판이에요.

**우리 적용** [추정]

- 생태계마다 `height(x, z)`와 단면 층 팔레트를 데이터로 정의해요.
  - 산호초: 흰 모래·석회암 층
  - 다시마 숲: 자갈·암반
  - 심해: 현무암·퇴적층에 열수구 근처 붉은 띠
  - 극지: 위쪽 얼음층 + 아래 암반, 수면 위 빙붕
- 사용자가 지형물을 놓는 게임이라, 배치 질의(높이·경사·점유)를 높이 함수 위에 두는 사례 구조를 그대로 써요.
- 블록 크기가 바뀌면 지형 분할 수를 블록 크기에 비례하게 정해요. 칸 간격 0.1~0.15가 기준이에요.

### 2.5 물고기 군집, 배의 부력과 경로

**물고기 Boids** [확인]

- 64마리, 몸통(납작하게 늘린 구) + 꼬리(원뿔)를 `mergeGeometries`로 합친 지오메트리 하나, `InstancedMesh` 1개, 인스턴스 색으로 5종을 구분해요.
- 매 프레임 모든 쌍을 비교해요(O(N²)).
  - 분리: 아주 가까운 이웃에서 (반경−거리)/거리 가중치로 밀어내요(모든 종).
  - 응집·정렬: **같은 종끼리만**, 중간 반경 안에서 해요.
  - 배회: 인덱스별 위상의 sin/cos 힘이에요.
  - 먹이: 일정 반경 안에서 가장 가까운 먹이로 끌려가고, 닿으면 먹어요.
  - 경계: 바닥 위·수면 아래 유지, 너무 얕으면 중심 쪽으로, 블록 벽에서 되밀기, 수직 속도 감쇠.
  - 속도를 최소·최대로 클램프하고 위치를 적분해요. 진행 방향의 y를 줄여 수평에 가깝게 기울이고, `setFromUnitVectors`로 회전해요.
- **몸의 헤엄 변형은 없어요.** 딱딱한 몸이 미끄러지듯 움직여요.

**배** [확인]

- 부력 `floatOn`:
  - 높이 = 수위 + h(x,z) − 흘수예요.
  - 기울기는 높이장의 중앙 차분 기울기를 배의 앞·옆 방향에 투영한 값의 arctan이에요.
  - 앞뒤·좌우 기울기는 `min(1, 6·dt)` 비율로 부드럽게 따라가요. 방향(요)은 경로 접선으로 정해요.
- 경로:
  - `CatmullRomCurve3`(닫힌 곡선 포함)의 `getPointAt`(호 길이 매개변수)으로 일정 속도로 움직여요.
  - 예인선은 목표점 추종 조향기를 써요(속도·방향을 비율로 수렴).
  - 요트는 타원 궤도를 돌고 바람에 비례해 기울어요.
- 항적 `wake`: 속도×dt에 비례해 선미에는 음의 교란(골), 선수에는 양의 교란(마루)을 넣고, 가끔 물보라를 뿜어요.
- 구명튜브: 중력 낙하 → 착수 때 큰 교란·물보라·소리 → 이후 수면 기울기를 따라 미끄러지고 마찰로 멈춰요. 육지에 닿으면 튕겨요.

**기타 움직임** [확인]

- 해초 120포기는 `InstancedMesh` 하나예요. **매 프레임 CPU에서 인스턴스 행렬 120개를 다시 써요**(위상별 sin/cos 회전).
- 갈매기는 날개 피벗 회전, 자동차는 `CurvePath` 위를 움직이는 인스턴스예요.

**우리 적용** [추정]

- 수백 마리면 O(N²)이 부담돼요. 균일 격자(공간 해시)로 이웃을 찾으면 O(N·k)예요. 종별 군집 규칙(응집·정렬은 같은 종끼리)은 그대로 가져와요.
- 몸 변형은 GPU로 옮겨요(3.1). CPU는 위치·방향·속도만 계산하고, 헤엄 위상은 셰이더가 `시간 × 속도`로 만들어요.
- 해초는 CPU 행렬 갱신 대신 셰이더 굽힘으로 바꿔요(CPU 0).

### 2.6 카메라 조작과 HTML 이름표

**카메라** [확인]

- 시야각 28°(좁은 화각 = 미니어처·디오라마 느낌)예요.
- OrbitControls: 감쇠 켬, 팬 끔, 거리 하한·상한, 극각 하한(정수리 바로 위 금지)·상한(수평보다 조금 위까지만), 왼쪽·오른쪽 버튼 회전, 가운데 버튼 돌리(dolly, 확대·축소).
- 기본 시점 거리는 화면 비율에 따라 늘어나요(세로 화면에서 더 멀리). 방위각·극각은 고정이에요. "시점" 버튼은 1.1초 easeOutCubic 보간으로 돌아가요.
- `setViewOffset`으로 데스크톱에서는 오른쪽 패널만큼 장면을 왼쪽으로 밀고, 좁은 화면에서는 위로 밀어요.
- 입력 분기: `pointerdown`을 캡처 단계로 받아 먼저 레이캐스트해요. 물·땅을 맞히면 컨트롤을 끄고 휘젓기·흔들기 모드로 가고, 빈 곳이면 컨트롤에 넘겨요. `userData.nopick` 조상이 있는 물체와 선 물체는 건너뛰어요. 더블클릭은 구명튜브, 오른쪽 버튼 메뉴는 막아요.

**이름표** [확인]

- `CSS2DRenderer`의 DOM을 화면 전체에 겹치고 `pointer-events: none`으로 둬요.
- 이름표마다 `CSS2DObject`를 **월드 그룹의 자식**으로 넣어요. 그래서 젤리 변형을 따라가요. 기준점은 아래 가운데(0.5, 1)예요.
- DOM 구조는 제목(+작은 부제) / 세로선 / 점이에요. CSS로 둥실거리는 애니메이션을 주고, 맛에 따라 색을 바꿔요. 켜고 끄기는 body 클래스로 해요.
- 비용: 이름표마다 매 프레임 DOM transform을 써요. 7개는 무시할 수 있지만 수백 개면 부담이에요.

**우리 적용** [추정]

- 극각 상한을 수평 근처(약 85~88°)까지 열어 **측면에서 물속을 들여다보는 시점**을 허용해요. "옆에서 보기" 프리셋 버튼을 둬요.
- 확대 하한을 낮춰 생물에 다가가게 하되, 블록 안으로 카메라가 들어가지 않게 블록 경계 + 여유로 막아요.
- 터치: OrbitControls는 한 손가락 회전, 두 손가락 확대를 지원해요 [추정·일반 지식]. "한 손가락으로 생물 누르기"와 겹치므로 사례처럼 "물체를 맞히면 상호작용, 빈 곳이면 회전"으로 나눠요.
- 이름표는 생물 수백 마리에 다 달지 말고, 생태계 랜드마크와 선택한 개체에만 달아요. 개체 선택 시 이름표 하나를 그 인스턴스 위치로 옮겨 써요.

## 3. 새로 만들 기법 (제안)

### 3.1 생물 자체의 젤리 표현

**방식 비교** [추정, 근거는 표 아래]

| 방식 | 개체별 다른 동작 | 드로우콜 | CPU | 장점 | 단점 |
|---|---|---|---|---|---|
| A. CPU 인스턴스 행렬 갱신(사례 해초 방식) | 위치·회전·크기만 | 종당 1 | 개체 수 × 행렬 | 단순 | 몸 굽힘 불가, CPU 비용 |
| **B. 인스턴싱 + 절차적 꼭짓점 셰이더** | 위상·속도·진폭을 인스턴스 속성으로 | 종당 1 | 위치·방향만 | 가장 싸고 무한히 다양함 | 법선·그림자·피킹을 따로 챙겨야 함 |
| C. 모프 타깃 + `InstancedMesh.setMorphAt` | 모프 가중치 | 종당 1 | 가중치 갱신 | 모델링 도구로 형태 제어 | 모델 파일 필요, 포즈 수 제한 |
| D. 스키닝(SkinnedMesh) | 뼈 애니메이션 | **개체당 1** | 뼈 행렬 × 개체 | 정교함 | 수백 개체면 CPU·드로우콜 폭증 |
| E. VAT(꼭짓점 애니메이션 텍스처) | 프레임 오프셋 | 종당 1 | 거의 0 | 복잡한 동작 재생 | 굽기 도구·텍스처 파일 필요 |

- B는 ABZÛ가 물고기 수천 마리에 쓴 방식이에요. 꼭짓점 셰이더에 좌우 이동·중심축 회전·몸통 파동·비틀림 네 동작을 넣고, uniform으로 세기를 조절하고, 개체마다 위상을 달리해요 [문서] — Godot 문서 "Animating thousands of fish with MultiMeshInstance3D" https://docs.godotengine.org/en/stable/tutorials/performance/vertex_animation/animating_thousands_of_fish.html (원 발표는 GDC "Creating the Art of ABZÛ"예요. 원 슬라이드는 확인하지 못했어요).
- D의 비용 문제는 three 포럼에 사례가 있어요. 스킨드 메시 100~1000개에서 CPU 시간 대부분이 믹서·뼈 갱신에 쓰였대요 [문서] https://discourse.threejs.org/t/optimization-of-large-amounts-100-1000-of-skinned-meshes-cpu-bottlenecks/58196
- E는 군중 렌더링에서 흔히 쓰지만, 우리는 이미지·모델 파일 없이 코드로 그리는 방향이라 B가 맞아요 [문서] https://discourse.threejs.org/t/one-draw-call-massive-crowd-performance-engineering-in-three-js/89928
- C의 `setMorphAt`과 D·E의 대안인 `BatchedMesh`는 r187 코어에 있어요 [확인].

**권고: B안** — 종마다 지오메트리 1개 + `InstancedMesh` 1개 + 공용 재질 1개에, 인스턴스 속성을 붙여요.

```
aPhase   float  위상(0..2π)
aSpeed   float  헤엄 주기 배율(CPU가 속도에 맞춰 갱신)
aParams  vec4   진폭, 굵기, 색 변형, 젤리 출렁임 세기 등 종 내 개체차
instanceColor   three 기본 인스턴스 색
uniforms        uTime, uCurrent(vec3, 해류 = 블록 가속도 + 기본 흐름), 종 공통 세기
```

**종별 변형식** (로컬 좌표, z = 머리→꼬리, 0..1로 정규화한 s 사용)

- 물고기 [추정, ABZÛ 방식을 제 식으로 정리]

```
ph   = uTime·ω·aSpeed + aPhase
mask = s²                                       // 머리는 거의 고정, 꼬리일수록 크게
x   += A_side · sin(ph)                          // 몸 전체 좌우 흔들림
x   += A_wave · mask · sin(ph - k·s)             // 몸통 파동(꼬리로 전파)
회전 y축 by A_pivot · sin(ph)                     // 중심축 요 흔들림
젤리감: z 방향 늘임 1 + J·sin(2·ph), x·y는 1 - J/2·sin(2·ph)    // 부피 보존 스쿼시
```

- 해파리 [실험: 아래 첫 두 줄은 r187에서 컴파일·렌더 확인] [추정: 비대칭 박동·추진]

```
pulse = 비대칭 곡선(빠르게 오므리고 천천히 풀림), 예: p = fract(t·f + aPhase); k = p<0.3 ? smoothstep(0,0.3,p) : 1 - smoothstep(0.3,1,p)
rim   = 갓 아래 테두리일수록 1인 마스크
xz   *= 1 - a·k·rim
y    *= 1 + b·k
CPU: k가 최대일 때 위쪽 속도 충격 → 천천히 가라앉음(박동과 이동이 맞물림)
촉수: 가는 띠/선 지오메트리, 길이 방향 s로 x += A·s·sin(ωt - λ·s + aPhase), 해류 uCurrent·s² 만큼 휨
```

- 해초·다시마·말미잘 촉수 [추정]

```
h    = 정규화 높이(0 뿌리 .. 1 끝)
bend = (uCurrent + A·vec3(sin(ωt + aPhase + 월드위치·κ), 0, cos(...))) · h²
pos += bend;  pos.y -= |bend|² · 0.5·h        // 길이 보존 근사(휘면 끝이 내려옴)
```

  월드 위치를 위상에 섞으면 "파도가 숲을 훑고 지나가는" 결이 생겨요. uCurrent에 블록 흔들림을 넣으면 블록을 흔들 때 숲이 함께 쏠려요.

- 접촉 젤리 반응(누르면 출렁) [추정]: 개체를 누르면 CPU에서 그 인스턴스의 감쇠 스프링 하나(2.1절과 같은 식)를 돌려 `aParams.w`(출렁 세기)만 갱신해요. 스프링이 멈추면 갱신도 멈춰요. 속성 버퍼는 바뀐 범위만 올려요(`addUpdateRange`).

**챙길 점**

- **그림자**: `onBeforeCompile`은 그림자 깊이 렌더에 쓰이는 재질에는 적용되지 않아요. 변형한 몸의 그림자를 맞추려면 같은 패치를 넣은 `customDepthMaterial`을 줘야 해요. r187 그림자 코드가 `customDepthMaterial`/`customDistanceMaterial`을 읽는 걸 확인했어요 [확인]. 다만 작은 생물은 그림자를 끄는 게 예산상 낫다고 봐요 [추정].
- **법선**: 변형 뒤 법선을 다시 계산하지 않으면 조명이 조금 어긋나요. 물고기 파동은 해석적으로 법선을 돌려 주고, 해파리·해초는 젤리 질감상 작은 오차를 허용해도 돼요 [추정].
- **피킹**: `Raycaster`는 `InstancedMesh`에서 `instanceId`를 돌려주지만 셰이더 변형 전 형태 기준이에요. 판정 구를 조금 키워 보완해요 [추정].
- **훅 위치**: `#include <begin_vertex>`(꼭짓점), `#include <normal_fragment_maps>`(법선), `#include <emissivemap_fragment>`(발광), `#include <color_fragment>`, `vec4 diffuseColor = vec4( diffuse, opacity );`가 r170·r187 모두 같은 개수로 있어요 [확인]. 사례 기법과 위 제안 모두 r187에서 그대로 쓸 수 있어요.

**생물 재질(젤리 질감)** [추정]

- 불투명 생물(물고기·불가사리·산호): `MeshPhysicalMaterial`에 클리어코트 1, 낮은 거칠기, 환경맵 반사를 써요. 프레넬 림(rim) 발광을 `totalEmissiveRadiance += rimColor · (1 − N·V)^p`로 넣고, 약한 자체발광으로 속이 비치는 느낌을 내요. 투과 없이 "젤리 사탕" 느낌이 나요.
- 반투명 생물(해파리·빗해파리): `transparent` + `DoubleSide` + 프레넬 불투명도(가장자리는 진하고 가운데는 투명)를 써요. **이 방식은 물 덩어리가 투과 재질이 아닐 때만 보여요**(2.2 실험, 3.2).

**실험 결과** [실험] (r187, WebGLRenderer, `InstancedMesh` 반구 200개 + `InstancedBufferAttribute` 위상 + `onBeforeCompile` 박동)

- 컴파일·렌더 오류가 없었어요. 해파리 200개가 그림자 없이 드로우 1회로 그려졌어요(장면 전체 6~7회).
- 인스턴스 색(`setColorAt`)이 투과 재질과 함께 동작했어요.
- 박동 변형이 눈에 띄는 정도는 정지 프레임 하나로는 판단하지 못했어요. 움직임은 실제 GPU에서 확인해야 해요.

### 3.2 물속 시점의 디오라마

#### 3.2.1 사례 방식을 그대로 쓰면 생기는 문제

1. **색이 죽어요** [실험]: 투과 물 벽 너머 생물은 흡수색(파랑)에 곱해져서 주황·분홍이 남색·청록이 돼요. 생물이 주인공인 우리 게임에는 치명적이에요.
2. **`transparent` 물체가 안 보여요** [실험·확인]: 투과 렌더 타깃에 반투명 물체가 들어가지 않아서, 물 안의 반투명 해파리·빛줄기·부유 입자가 바깥에서 사라져요.
3. **깊이감이 없어요** [확인]: 흡수 길이가 실제 경로가 아니라 고정 `thickness`라, 가까운 물고기와 먼 바위가 같은 비율로 물들어요.
4. **비용이 커요** [실험]: 투과 패스 하나가 불투명 물체 전체를 다시 그려요(사례 432회).

#### 3.2.2 제안: 투과 없는 물 덩어리 [추정, 시제품 검증 필요]

물 덩어리를 세 층으로 나눠요.

```
① 물속 물체(지형·생물·소품): 불투명(또는 반투명) + "물속 안개" 셰이더 주입
② 물 박스 뒷면(BackSide): 반투명, 색 = 물색, 알파 = 1 - T(박스 안 경로 길이)
③ 물 박스 앞면 + 수면: 반투명 광택층(클리어코트 + 환경맵 + 프레넬 불투명도 + 수면선)
그리기 순서: ①(불투명 큐) → ② → 빛줄기·부유 입자 → ③   (renderOrder로 고정)
```

**물속 안개 식** (모든 물속 재질에 같은 GLSL 조각을 주입해요)

```
입력: 프래그먼트 월드 위치 P, 카메라 C, 물 박스 AABB(윗면 = 수위), 흡수 계수 σ(vec3), 물색 W(depth)
d      = normalize(P - C)
tEnter = 슬랩(slab) 방식 광선-상자 교차의 진입 t, 0 이상으로 클램프(카메라가 밖이면 박스 표면)
L      = max(0, |P - C| - tEnter)                // 물속을 지나온 실제 거리
T      = exp(-σ · L)                             // 채널별 투과율(빨강이 가장 빨리 줄어요)
depth  = 수위 - P.y
light  = exp(-σd · depth)                        // 위에서 내려온 빛이 깊이에 따라 줄어듦
color  = color · light · T + W(depth) · (1 - T)
```

- 가까운 생물은 제 색이 살고, 멀고 깊은 것만 물색에 잠겨요. 실제 물속처럼 보여요. σ는 생태계별로 정해요(산호초는 맑게, 다시마 숲은 녹청, 심해는 짙고 어둡게).
- ②의 뒷면도 같은 식으로, P = 뒷면 점으로 계산해요. 물체가 없는 곳은 박스를 통과한 거리만큼 물색이 진해지고, 얇은 모서리 쪽은 배경이 비쳐요. 물체가 있는 곳은 깊이 테스트로 가려져요.
- ③은 사례의 젤리 광택(클리어코트·강한 정반사·환경맵)을 그대로 살려요. 투과가 없으니 굴절 일그러짐은 없어요. 대신 프레넬로 비스듬한 각도에서 진해지게 해서 유리 덩어리 느낌을 내요.
- 수면을 아래에서 볼 때: 수면 메시 뒷면은 밝은 프레넬 + 커스틱 무늬로 칠해요(스넬의 창 흉내).
- 비용: 투과 패스가 사라져요(사례 기준 프레임당 약 1/3 절감). 안개 조각은 프래그먼트당 산술 20여 개예요.
- 위험: 반투명 ②·③과 반투명 생물 사이의 정렬 오류예요. 물체 단위로 정렬하므로 해파리끼리 겹칠 때 순서가 틀릴 수 있어요. 해파리는 `depthWrite` 끔 + 가산에 가까운 혼합으로 순서에 덜 민감하게 만들어요.

#### 3.2.3 빛줄기 [추정]

- 수면에서 비스듬히 내려오는 가늘고 긴 판(또는 끝이 열린 원뿔) 메시 4~10장을 한 지오메트리로 합쳐 드로우 1회로 그려요. 가산 혼합, `depthWrite` 끔이에요.
- 알파 = 길이 방향 감쇠 × 가장자리 부드러움 × 시간에 따라 흐르는 1D 노이즈(커스틱과 같은 시간)로 일렁이게 해요. 카메라를 정면으로 마주할수록 옅게 해서 판의 모서리가 드러나지 않게 해요.
- 수면이 출렁일 때 빛줄기 세기를 살짝 흔들어 연동해요.
- 화면 공간 갓레이 후처리는 쓰지 않아요. 공식 WebGPU 체적광 예제와 `three-good-godrays` 같은 후처리가 있지만 [문서] https://discourse.threejs.org/t/volumetric-lighting-in-webgpu/87959 , 노트북에서 화면 전체 패스가 추가되고 WebGPU나 별도 후처리 라이브러리가 필요해요.

#### 3.2.4 부유 입자(마린 스노) [추정]

- `Points` 하나에 수천 개를 둬요. CPU 갱신 없이 꼭짓점 셰이더에서 `pos = mod(초기위치 + 흐름속도·t + uCurrent적분 - 박스최소, 박스크기) + 박스최소`로 박스 안을 순환시켜요.
- 크기는 사례 물보라처럼 1/깊이로 보정하고, 벽 근처에서 페이드해요. 물속 안개 T도 적용해요. 프래그먼트는 사례 물보라처럼 부드러운 원이에요.
- 드로우 1회, CPU 0이에요. 블록 흔들림 가속도를 uCurrent에 넣으면 입자도 함께 쏠려요.

#### 3.2.5 깊이에 따른 색과 생태계별 조명 [추정]

| 생태계 | 물색(얕음→깊음) | σ(흡수) | 특이 요소 |
|---|---|---|---|
| 산호초 | 청록 → 하늘파랑 | 낮음(맑음) | 커스틱 강하게, 빛줄기 많이 |
| 다시마 숲 | 녹청 → 짙은 청록 | 중간 | 다시마 굽힘, 빛줄기가 숲 사이로 |
| 심해 | 남색 → 거의 검정 | 높음 | 커스틱 없음, 생물발광(자체발광 + 가산 후광 스프라이트로 가짜 블룸) |
| 극지 | 회청 → 짙은 청회 | 중간 | 수면 위 빙붕·유빙(불투명 젤리 얼음), 위에서 새는 차가운 빛 |

- 심해 생물발광은 블룸 후처리 대신 개체 위에 가산 혼합 원형 스프라이트(인스턴스)를 겹쳐 흉내 내요. 드로우 1회예요.

### 3.3 MVP: 몰디브형 열대 바다 — 물 위와 물속을 한 블록에 [추정]

대니님 지침(2026-11-11, 메인 세션 전달): MVP 생태계는 작은 섬들이 있는 열대 바다 하나예요. 한 블록에 모래섬·야자수, 얕은 석호, 산호초, 깊어지는 바깥 바다가 함께 들어가요. 인공물은 섬 위, 해저, 수중 세 곳에 놓여요.

#### 3.3.1 섬과 해저를 하나의 지형으로

사례도 섬과 해저를 높이 함수 하나로 만들어요 [확인, 2.4]. 우리도 **높이장 하나 + 수위 하나**로 가요. 물 위인지 아래인지는 메시를 나누지 않고 셰이더가 프래그먼트마다 `y`와 수위를 비교해서 정해요.

```
r      = 환초 중심에서의 거리(약간의 fbm으로 일그러뜨림)
base   = 바깥 바다 바닥: 블록 가장자리로 갈수록 급히 깊어짐 (예: -D_deep · smoothstep(r_reef, r_edge, r))
reef   = 고리 모양 산호 둑: 원환 SDF  |r - r_reef| - w_reef  → 수위 바로 아래까지 솟음
lagoon = 둑 안쪽 얕은 분지: 수위 아래 얕은 일정 깊이 + 저주파 노이즈(모래 언덕)
motu   = 작은 모래섬들: 원·캡슐 SDF 몇 개, 수위 위 낮게(해변 경사는 smoothstep 폭으로)
bommie = 석호 안 산호 덩어리: 작은 원 SDF + 고주파 노이즈, 수위 아래
h = smax(base, reef, lagoon, motu, bommie)   // 사례처럼 max 합집합, 경계가 각지지 않게 부드러운 max
```

- 지대 판정(색·배치 규칙)은 **수위 기준 높이 띠**로 해요: 섬 안쪽(풀·야자) / 마른 모래 / 젖은 모래(수위 ±ε, 파도 거품 띠) / 석호 흰 모래 / 산호 둑 / 바깥 경사면 / 깊은 바닥.
- 지층 단면도 같은 높이 함수로 잘려요. 섬 밑으로 산호 석회암 층, 석호 밑 흰 모래 퇴적층이 보여요.
- 물 격자의 `wall` 마스크가 섬을 자동으로 육지 처리하니, 섬 해안에서 파도가 반사되고 거품이 생겨요 [확인된 사례 동작을 그대로 씀].

#### 3.3.2 물 위·물 아래·경계에 걸친 인공물

- 모든 재질이 같은 셰이더 조각 슬롯을 쓰고, 조각이 프래그먼트마다 `y < 수위`일 때만 안개·깊이 감쇠·커스틱을 켜요. 그래서 **한 물체가 수면을 가로질러도 위는 맑게, 아래는 물에 잠겨 보여요.** 물 위 방갈로의 기둥, 잔교, 반쯤 잠긴 난파선, 부표가 별도 처리 없이 맞게 그려져요.
- 경계선이 너무 칼같지 않게 수면 근처 ±ε에서 부드럽게 섞어요. 수면 높이는 파도로 출렁이므로 조각에 수면 높이장을 데이터 텍스처로 넘기면 더 정확해요(선택).
- 배치: 섬 위(지형 높이에 붙임), 해저(지형 높이 + 경사 정렬), 수중(지형과 수면 사이 아무 높이, 부유물은 부력)으로 배치 질의를 나눠요.

#### 3.3.3 카메라: 수면 위에서 옆, 그리고 물속까지

- **기본(블록 밖 관찰)**: 극각을 위에서 내려다보기 ↔ 거의 수평 측면까지 연속으로 열어요. 위에서는 석호 바닥이 비치는 수면을, 옆에서는 물 벽 너머 산호초와 그 위 섬·야자수를 한 화면에 봐요. 카메라는 늘 블록 밖이라 물속 안개 식의 진입점이 박스 표면이에요(3.2.2).
- **선택: 물속 들어가기 모드**: 카메라가 블록 안 수면 아래로 내려가면
  - 진입점 `tEnter = 0`(카메라가 이미 물속), 배경색을 물색으로 바꿔요.
  - 수면 메시 뒷면을 밝은 프레넬 + 커스틱으로 그려요(스넬의 창 흉내).
  - 카메라 xz의 수면 높이를 표본해서 위·아래 상태를 0.2초쯤 걸쳐 보간해요. 렌즈가 수면에 반쯤 걸친 장면(화면 절반은 물 위, 절반은 물속)은 화면 분할 처리가 필요해 비싸요. 카메라가 수면 ±ε 띠에 머물지 못하게 그 띠를 건너뛰게 해요.
  - MVP는 기본 모드만으로도 "물 위와 물속을 함께 본다"는 목표를 채워요. 물속 들어가기는 그다음 단계로 미루는 걸 권해요.

#### 3.3.4 수면 경계의 굴절·반사

| 처리 | 방법 | 비용 | 권고 |
|---|---|---|---|
| 반사 | 환경맵(RoomEnvironment 또는 하늘 그라데이션) + 프레넬. 비스듬히 볼수록 하늘을 많이 반사 | 거의 0 | **채택** |
| 평면 반사 | `Reflector` 애드온(r187에 있음 [확인])으로 장면을 거울 시점에서 한 번 더 그림 | 장면 전체 1회 추가 | 보류(드로우콜 2배) |
| 진짜 굴절 | 투과 재질(화면 복사본 굴절) | 불투명 전체 1회 추가 + 반투명 소실(3.2.1) | 보류 |
| 굴절 흉내 | 수면 법선(잔물결)으로 물속 바닥 셰이더의 커스틱·바닥 무늬 좌표를 살짝 흔듦. 수면 위에서 볼 때만 | 거의 0 | **채택** |
| 수면선 | 물 벽 위 흰 띠(사례 기법) + 그 바로 아래 옅은 어두운 띠(메니스커스 느낌) | 0 | **채택** |

- 위에서 내려다볼 때 수면 불투명도를 프레넬로 정해요. 수직에 가까우면 거의 투명해서 석호 바닥이 선명히 비치고(몰디브 사진의 그 느낌), 비스듬하면 하늘 반사가 강해져요.

#### 3.3.5 얕은 열대 바다의 물빛과 깊이별 색

- 맑은 열대 바다는 빨강을 강하게, 초록을 중간, 파랑을 약하게 흡수해요. 흰 모래 위의 얕은 물이 청록으로 보이는 건 빛이 **내려가고 다시 올라오는** 두 번의 경로를 거쳐서예요.

```
위에서 본 바닥 색 ≈ 모래색 · exp(-σ · (depth + depth / cosθ_view)) + 산란색 · (1 - exp(-σs · 경로))
σ(빨강) ≫ σ(초록) > σ(파랑)          // 몰디브형: 아주 맑음 → σ 작게, 산란 약하게
```

- 결과: 석호(깊이 얕음)는 밝은 청록, 산호 둑 위는 더 밝은 하늘색, 둑 바깥 경사면에서 급히 남색으로 떨어져요. 바깥 바다의 짙은 파랑은 박스 뒷면 물색(긴 경로)과 깊은 바닥의 안개가 만들어요.
- 이 식은 3.2.2 안개 식에 "빛이 내려온 깊이" 항을 더한 것이라 같은 조각 하나로 처리돼요.

### 3.4 생태계별 물 프로필 [추정]

물빛·탁도·조명을 **셰이더를 바꾸지 않고 uniform 묶음만 바꿔** 생태계를 갈아 끼우게 해요. 확장 후보(온대 남해안, 한대, 아마존 민물 호수)는 모두 같은 조각으로 표현할 수 있어요.

```
WaterProfile {
  absorption   vec3   // σ: 채널별 흡수. 빨강이 크면 푸르게, 파랑이 크면 갈색·녹색으로
  scatter      vec3   // 산란 색(탁한 물일수록 밝고 뿌옇게)
  turbidity    float  // 산란 세기·가시거리. 클수록 가까운 것도 흐려짐
  shallowTint  vec3   // 얕은 바닥 위 보정 색
  causticGain  float  // 커스틱 세기(탁하면 약하게)
  shaftCount   int    // 빛줄기 수
  particleDensity float // 부유 입자 밀도
  waveAmp      float  // 수면 물결 세기(호수는 작게)
  foam         float  // 해안 거품(민물은 거의 0)
}
EnvProfile { hemiSky, hemiGround, sunColor, sunDir, background, envIntensity }
```

| 생태계 | 흡수(빨/초/파) | 탁도 | 조명 |
|---|---|---|---|
| 열대(몰디브, MVP) | 빨강만 크게, 전체 작게 | 아주 낮음 | 높은 태양, 따뜻한 흰빛, 커스틱·빛줄기 강함 |
| 온대(남해안) | 빨강 크게 + 파랑도 조금 → 녹청 | 중간(플랑크톤) | 비스듬한 태양, 녹청 산란, 다시마 숲 그늘 |
| 한대 | 작게(맑고 차가움) | 낮음 | 낮은 태양, 회청 하늘, 얼음 천장 아래 확산광 |
| 아마존 민물 호수 | **파랑을 크게**(탄닌으로 갈색·차색) | 높음 | 숲 그늘의 녹황 빛, 빛줄기는 가늘고 적게, 커스틱 약함, 물결·거품 거의 없음 |

- 높이장·수면·안개·커스틱 코드는 공통이고, 프로필만 다르게 넣어요. 바다·민물 구분은 거품·파도 세기·생물 목록의 차이예요.
- 블록 전환 때 두 프로필을 보간하면 "생태계가 물들어 가는" 연출도 가능해요.

### 3.5 드로우콜 예산

**사례 분석** [실험] (800×500, r170·r187 같음)

| 패스 | 드로우콜 | 원인 |
|---|---|---|
| 그림자 맵 | 416 | 메시 439개 중 416개가 `castShadow` |
| 투과 렌더 타깃 | 432 | 투과 재질(물)이 있어 불투명 물체 전체를 다시 그림 |
| 본 화면 | 441 | 메시 439개(그중 `InstancedMesh` 17개) + 점·선 |
| **합계** | **1,289** | 같은 물체를 세 번 그림 |

재질은 89개예요. 그런데 공유 재질이 많은데도 드로우콜이 줄지 않았어요. 재질 공유는 셰이더 전환을 줄일 뿐 **드로우콜 수는 줄이지 않아요.** 드로우콜을 줄이는 건 합치기·인스턴싱이에요 [추정·일반 원리].

**교훈**

1. 드로우콜 = (그릴 물체 수) × (그 물체가 들어가는 패스 수)예요. 물체 수와 패스 수를 함께 줄여야 해요.
2. 투과 재질 1개가 패스 하나를 통째로 추가해요 [확인].
3. 작은 정적 소품(상자 하나하나)이 물체 수 대부분을 차지해요 [확인].

**전략** [추정]

| 대상 | 방법 | 결과 |
|---|---|---|
| 지형·단면·바닥 | 생태계당 지형 1 + 단면 1(4면 합침) + 바닥 1 | 3회 |
| 사용자가 놓는 지형물(바위·산호·난파선·관측소 등) | **`BatchedMesh` 1개**에 종류별 지오메트리를 `addGeometry`하고 배치마다 `addInstance`. 추가·삭제·이동 때 다시 합칠 필요 없어요 [문서: Context7 r186 BatchedMesh] | 재질 계열당 1회 |
| 생물 | 종당 `InstancedMesh` 1개(3.1) | 종 수만큼 |
| 물 | 수면 1 + 거품 1 + 뒷면 1 + 앞면 광택 1 | 4회 |
| 효과 | 물보라 1 + 부유 입자 1 + 빛줄기 1 + 생물발광 후광 1 | 4회 |
| 그림자 | 큰 정적 물체만 그림자를 드리워요. 정적 그림자는 `renderer.shadowMap.autoUpdate = false`로 두고, 배치가 바뀔 때만 `needsUpdate = true` [확인: r187 소스에 해당 분기 있음]. 생물 그림자는 끄거나 바닥에 둥근 가짜 그림자(인스턴스 1회) | 평소 0회 |
| 투과 | 쓰지 않음 | 0회 |
| 재질 | 공용 팔레트 재질 몇 개 + 꼭짓점 색·인스턴스 색. 재질 종류 10개 안팎 | 셰이더 전환 최소 |

- `BatchedMesh`는 서로 다른 지오메트리를 드로우 1회로 그리고, 인스턴스별 행렬·색·보이기를 바꿀 수 있어요 [문서]. 사용자가 늘 배치를 바꾸는 가꾸기 게임에 잘 맞아요. `onBeforeCompile` 주입이 `BatchedMesh`에서도 같은 훅으로 동작하는지는 확인하지 못했어요. 시제품 1순위 확인 항목이에요 [추정].

### 4.3 WebGLRenderer vs WebGPURenderer(TSL)

| 기준 | WebGLRenderer | WebGPURenderer |
|---|---|---|
| `onBeforeCompile`, `ShaderMaterial` | 지원 | **미지원.** 노드 재질·TSL로 다시 써야 해요 [문서] |
| 후처리 | EffectComposer | 별도 노드 후처리 스택, EffectComposer 미지원 [문서] |
| 성숙도 | 성숙, 유지보수 중, 큰 신기능 계획 없음 [문서] | "아직 실험적", 장면에 따라 기능 누락이나 WebGL보다 느린 경우가 있다고 문서에 적혀 있어요 [문서] |
| 대체 경로 | — | WebGPU가 없으면 WebGL2 백엔드로 자동 대체, `await renderer.init()` 필요 [문서] |
| 이 환경 검증 | SwiftShader WebGL2로 가능 [실험] | `navigator.gpu` 없음 → WebGPU 경로 검증 불가 [실험] |
| 장점 | 사례 기법 직이식, 자료 많음 | 컴퓨트 셰이더(군집·물 시뮬을 GPU로), TSL 하나로 WGSL/GLSL |

출처: three r186 문서 `manual/pages/webgpurenderer.html`, `docs/llms.txt`(Context7 `/mrdoob/three.js/r186`로 조회).

**권고: WebGLRenderer** [추정]

- 우리 핵심 기법(물속 안개, 생물 변형, 커스틱, 지층)이 모두 "기본 재질 + 셰이더 조각 주입"이에요. WebGL에서는 사례처럼 짧게 쓸 수 있어요.
- 원격 환경에서 녹화 모드로 검증할 수 있는 건 WebGL뿐이에요.
- 군집·물 시뮬레이션은 지금 규모에서 CPU로 충분해요. 컴퓨트 셰이더가 꼭 필요한 규모(개체 수천 이상)가 되면 그때 다시 따져요.
- 이전 대비책: 주입 조각을 `render/shaderPatches.js` 한곳에 모으고, 재질 생성은 팩토리 함수로만 해요. 나중에 TSL로 옮길 때 그 모듈만 바꾸면 돼요.

### 4.4 vendor·오프라인 PWA 방식 [추정, 저장소의 기존 PWA 구조 참고]

```
games/ocean-world-3d/
  vendor/three-0.187.0/
    LICENSE
    build/three.module.js
    build/three.core.js
    examples/jsm/controls/OrbitControls.js
    examples/jsm/environments/RoomEnvironment.js
    examples/jsm/renderers/CSS2DRenderer.js

```

```html
<script type="importmap">
{ "imports": {
  "three": "./vendor/three-0.187.0/build/three.module.js",
  "three/addons/": "./vendor/three-0.187.0/examples/jsm/"
} }
</script>
```

- 파일은 npm 패키지(`npm pack three@0.187.0`)에서 그대로 복사해요. 내용을 고치지 않아요. 경로에 버전을 넣어 두면 서비스 워커에서 **캐시 우선**으로 처리해도 안전해요(내용이 절대 안 바뀌어요).
- 저장소 `games/animal-world/sw.js`는 게임 파일 네트워크 우선 + 글꼴 캐시 우선 구조예요 [확인]. 같은 틀에 "vendor 경로는 캐시 우선"만 더하면 돼요. 설치 캐시 목록에 core와 module **둘 다** 넣어야 해요(core가 빠지면 오프라인에서 import가 실패해요).
- 압축 파일이 없어 2.1MB예요. 첫 설치 때 한 번만 받으니 노트북 PWA에는 문제없다고 봐요. 줄이고 싶으면 r185.0의 `.min.js`를 쓰는 선택지가 있지만, 최신 수정을 포기해야 해요. r187 비압축을 권해요(디버깅할 때 읽기도 쉬워요).
- r187은 배포 12일째예요. 시제품 단계에서 문제가 생기면 `0.186.1`로 내리는 것도 import map 두 줄만 바꾸면 돼요.
- 사례처럼 Google Fonts를 쓰면 오프라인 첫 실행 전에 한 번은 온라인이어야 해요. 기존 sw처럼 글꼴을 캐시하거나 시스템 글꼴을 써요.

| 항목 | 이유 | 다음 확인 방법 |
|---|---|---|
