## 0. 한눈에

- **마감 선언**: 대니님이 이번 사이클의 결과를 "MVP 완료로 간주"하고 여기서 결산하기로 했어요(2026-11-11).

- **어디에 있나**: 전부 통합 브랜치 `claude/stoic-ramanujan-csbrar`의 `games/ocean-world-3d/`. **`main`에는 없어요.**

코드는 Three.js 원본을 빼고 약 5,800줄이에요.

### 3.2 실행

```bash
git fetch origin && git checkout claude/stoic-ramanujan-csbrar
cd games/ocean-world-3d
python3 -m http.server 8000        # 시제품: http://localhost:8000/
npm test                            # 규칙 테스트 66개
node tools/sim.js --table 5         # 밸런스 봇 표(임시 격자)
node tools/sim.js 240 7 0.6 1 1.5 --terrain=eco/atoll/terrain.js   # 실제 지형으로 한 번
node tools/capture.mjs --out <폴더> --views default,side,top --water box --frames 40 --jpeg 0.85   # 화면 찍기
```

시제품 주소 옵션: `perf=1`(성능 표시·측정) · `water=box|transmission` · `n=`(생물 수) · `sizes=S,M,L,XL`(크기 배율, `1`이면 원래) · `sigma=`(물 탁도) · `jelly=`(출렁임 세기, 0이면 끔) · `view=` · `ext=1`(확장 영역까지) · `lineup=1`(종마다 한 마리 줄 세우기) · `capture`(녹화 모드) · `title=1`.

### 3.3 구조의 뼈대(PLAN.md 3절)

- `sim/`은 Three.js·DOM·생태계 이름을 모르고, `eco` 객체를 인자로 받아요. 물 없는 육지 생태계 데이터로도 도는 테스트가 있어요.
- `render/core/`(생태계 무관)는 `render/aqua/`(물 전용)를 import하지 않아요. 셰이더 조각 주입은 `render/core/materials/shaderPatches.js` 한 곳이에요.
- 지형 정의는 `eco/atoll/terrain.js` 한 곳이고, 규칙과 화면이 같은 함수를 읽어요.
- 생물·물건 생성기는 지금 `render/proto/`에 임시로 있어요. 자리는 `eco/atoll/species/`·`props/`예요.

### 4.1 메인 세션이 직접 확인한 것

| 항목 | 방법 | 결과 |
|---|---|---|
| 규칙 테스트 | 통합 브랜치에서 `npm test` | 66개 통과 |
| 밸런스 봇 | `--table 5` 직접 실행 | 활동 플레이 T8 92~99분 · 가끔 136~149분 · 방치 220분(Animal World 활동 80~102분). 임시 격자 기준 |
| 실제 지형으로 봇 | 시드 7 한 번 | T8 88.9분, 240분 뒤 물건 578개 |
| `sim/` 독립성 | grep | Three.js·DOM·생태계 이름 없음 |
| 시제품 화면 | 녹화 모드로 직접 찍음(반영 전 8장, 반영 후 3장) | 콘솔 오류 없음. 투과 없는 물, 수면을 가로지르는 기둥, 타이틀이 보고서대로 보임 |
| 드로우콜·삼각형 | 녹화 모드 통계 | 프레임당 19회 / 226,074개(목표 300회 이하). 참고 사례 방식은 29회 / 333,298개 |
| 두 물 방식 차이 | 화면 | 참고 사례 방식(투과)에서는 해파리가 사라지고 물속 색이 어두워짐 |
| 대니님 방향 반영 | 반영 전후 화면을 나란히 비교 | 물빛이 한 단계 밝아지고, 옆에서 봤을 때 생물이 중층·깊은 곳까지 퍼짐 |
| Three.js 파일 | npm 원본과 `cmp` | 5개 파일 바이트 단위로 같음 |
| 맡은 파일 범위 | `git diff --name-only` | 하위 세션마다 맡은 곳만 바뀜 |
| 기초 사실 | PyPI·npm 직접 조회 | sand3d는 Python 모델링 라이브러리(Apache-2.0), Three.js 최신은 0.187.0 |

### 4.2 하위 세션의 보고로만 남은 것(메인 세션이 다시 재지 않음)

- 분포 수치: 헤엄 생물의 깊은 곳 체류가 물 부피 몫의 0.85~1.32배(규칙), 칸두 체류 비율 흰동가리 12 → 51% 등(시제품). 테스트(`test/balance.test.js`)가 0.5~1.6배 범위를 걸고 있고 통과는 확인했어요.
- 새 크기로 다시 한 밀도 계산(A안 충분, 비 2.94).
- 생물끼리 겹치는 쌍 비율 0.20 → 0.22%.
- `BatchedMesh`에 셰이더 조각 주입이 된다는 것(컴파일된 셰이더 소스 확인은 하위 세션이 함. 화면에서 기둥의 물속 부분만 물빛에 잠기는 것은 메인 세션도 봄).
- 무료 에셋 라이선스 조사(Quaternius가 재배포 금지로 바뀜, Hunyuan3D가 대한민국에서 적용 안 됨 등). 각 문서에 "확인함 / 검색만 / 확인 못 함" 표시가 있어요.
- 몰디브 생태 점검(보름달물해파리 빈도, 맹그로브 유무 등)은 "확인 필요"로 남아 있어요.

### 4.3 아무도 확인하지 못한 것

- **노트북의 프레임 속도.** 드로우콜은 적지만, 물속 안개와 커스틱은 픽셀마다 계산이라 실제 부담은 재 봐야 알아요.
- 움직임이 생동감 있게 보이는지, 젤리 출렁임의 느낌, 밝아진 물빛이 실제 화면에서 어떤지.
- 터치 기기에서의 조작.
- 컨텍스트 손실(GPU 자원 회수) 복구.

## 5. 알려진 문제와 열린 항목

| 항목 | 내용 | 근거 |
|---|---|---|
| 규칙과 화면이 떨어져 있음 | 시제품의 `render/proto/wander.js`를 `sim/`이 주는 상태로 바꿔야 해요. 넘길 상태의 모양은 `docs/p1-sim-report.md` 3절 | 보고서 두 건 8절·3절 |
| 크기·속도 값이 두 군데 | 규칙 쪽 `eco/atoll/data.js`(`SIZES[].draw`, 속도)와 시제품 쪽 `render/proto/species.js`(`SIZE_SCALE`, 속도)가 따로예요. 출발값은 같지만 생동감 조정값은 서로 달라요(예: 해파리 0.45 대 0.36칸/초). 결합할 때 데이터 한 곳으로 모아야 해요 | 두 보고서 |
| 물건 개수 상한 없음 | 수중 3층 때문에 같은 자리에 4겹으로 놓을 수 있어, 봇 240분에 물건 580~750개·발전도 약 3,800~4,350(Animal World 약 1,800). 규칙에 상한 자리가 없고, 넣을 곳은 `docs/p1-sim-report.md` 12절 | 대니님이 시제품 평가 때 검토하기로 함 |
| "먹으러 가기"를 없앰 | 분포가 치우치는 가장 큰 원인이어서 헤엄 생물은 제자리에서 먹고 쉬게 바꿨어요. 물건을 놓았을 때 생물이 모여드는 반응이 사라져요 | 규칙 세션 보고. 대니님 판단 필요 |
| 확장 영역 지형 | 본 블록 지형을 그대로 이어 붙인 임시 상태. 칸두 끝이 절벽처럼 끊겨요 | 시제품 보고서 7절 |
| 분포 테스트의 구역 나눔 | `test/balance.test.js`가 임시 격자(확장이 `+y`) 기준. 실제 지형은 `+x`라 `areaOf`를 고쳐야 해요 | 규칙 보고서 13.5절 |
| 테스트가 임시 격자 기준 | `test/fixtures/atoll-grid.js`로 돌아요. 실제 지형으로는 봇만 돌려 봤어요 | 규칙 보고서 10절 |
| 지형 비율 | 틸라(물속 봉우리)가 전체의 약 4%로 설계 가정(20%)보다 훨씬 작고 얕은 곳이 넓어요 | 시제품 보고서 6절 |
| 위에서 본 석호가 희게 바램 | 물빛을 밝게 한 뒤에도 더 나빠지지는 않았다고 보고됨. 값은 `eco/atoll/profile.js` | 시제품 보고서 7·10.4절 |
| 등급 차이가 줄어듦 | 대형 거북 2.38칸과 중형 말미잘·문어 2.2칸의 차이가 0.18칸 | 시제품 보고서 10.1절 |
| 생물 그림자 없음 | 변형된 몸과 그림자가 어긋나서 끔. 높이가 덜 읽혀요 | 시제품 보고서 7절 |
| 탭 판정 | 블록 판정만 있고 생물·물건 고르기는 없어요 | 시제품 보고서 8절 |
| 아래 시점의 수면 | 수면 밑면이 단순 물색 | 시제품 보고서 7절 |
| 보고서 3절 비교 그림 | 물빛을 바꾸기 전 그림이에요 | 시제품 세션 메시지 |

## 8. 하위 세션 위임에서 배운 것

- **맡은 폴더를 미리 나누고 맞닿는 부분(지형 함수의 모양)을 먼저 정해 준 것**이 잘 통했어요. 두 세션이 동시에 일했는데 합칠 때 충돌이 없었고, 규칙이 실제 지형을 고치지 않고도 그대로 읽었어요.
- **"확인함"과 "추정"을 구분해 보고하게 한 것**이 검증을 빠르게 했어요. 메인 세션이 다시 잰 수치(테스트 개수, 봇 표, 드로우콜)는 모두 보고와 같았어요.
- **녹화 모드를 처음부터 넣은 것**이 원격 검증의 전부였어요. 소프트웨어 GPU에서도 한 장에 10~25초면 찍혀요.
- **하위 세션은 메시지를 보내올 수 있어요.** 처음에는 못 보내는 줄 알고 30~45분 뒤 확인을 예약했는데, 끝나면 스스로 알려 왔어요.
- **사용량 한도**: 시제품 세션이 마지막 단계에서 한도에 걸려 3시간쯤 멈췄다가 스스로 이어서 끝냈어요. 메인 세션도 같은 시간 멈췄어요. 큰 작업을 동시에 여럿 띄울 때는 한도를 감안해야 해요.
- **메인 세션의 실수**: 날짜를 2026-11-12로 잘못 적어 계획서와 하위 세션 문서 23곳을 고치게 했어요. 설계 초안이 조사 문서의 번호(WP1·WP2)를 바꿔 적은 것도 초안 머리말의 안내로만 막았어요.
- **조사가 처음 가정을 뒤집은 곳**: sand3d는 AI 생성 모델이 아니었고, 무료 에셋은 화풍과 라이선스 때문에 쓰기 어려웠고, 참고 사례의 물 표현(투과)은 물속 생물이 주인공인 게임에 맞지 않았고, "수직축이 있어 흩어지기 유리하다"는 화면 기준으로는 거의 맞지 않았어요.
