고치지 않은 곳(맡은 범위 밖): `render/proto/`, `render/main.js`, `index.html`, `sim/`, `ui/`, `eco/atoll/data.js`. `render/core/materials/shaderPatches.js`도 고치지 않았어요. 새 셰이더 조각은 기존 훅(`vertexPars`·`vertexDeform`·`vertexNormal`·`fragmentEmissive`·`fragmentOutput`)으로 다 들어갔어요 [확인: `patchStats().missingHooks` 0건]. 게임 본 화면에는 끼우지 않았어요.

`eco/atoll/species/*.js`는 three를 import하지 않고 `THREE`를 인자로 받아요. 그래서 Node에서도 import·생성이 돼요 [확인: Node 26에서 6개 조합 생성, NaN 없음].

## 2. 생성기 약속(P2·메인 세션이 붙일 때)

### 2.1 함수 모양

```js
import * as moonjelly from '../eco/atoll/species/moonjelly.js';
const kit = moonjelly.build(THREE, { variant: 'jelly' | 'lowpoly', detail: 1 });
```

| 내보내는 것 | 뜻 |
|---|---|
| `id` | 종 id. `eco/atoll/data.js`의 `SPECIES` 키와 같음(`moonjelly`, `clownfish`). 장식 떼는 `chromis`(data.js에 없음, 규칙 무관) |
| `variants` | `{ jelly: '매끈한 젤리풍', lowpoly: '그래픽 로우폴리풍' }` |
| `build(THREE, opts)` | 아래 객체를 돌려줌 |
| `pulse(t, speed, phase)` | 해파리만. 박동 곡선 0..1. 셰이더와 같은 식이라 CPU 추진(박동할 때 위로 밀기)을 맞출 때 씀 |

`opts`: `variant`(기본 `'jelly'`), `detail`(젤리풍 분할 배율 0.4~1, 기본 1. 먼 시점용으로 줄일 수 있음). **크기·속도·개체 수는 받지 않아요.** 수치의 정본은 `eco/atoll/data.js`예요. 화면 크기는 배치하는 쪽이 `len × SIZES[size].draw`를 인스턴스 행렬의 균일 배율로 곱해요(P1 `main.js`가 하던 방식 그대로).

`build`가 돌려주는 객체

```js
{
  id, variant,
  geometry,   // THREE.BufferGeometry(index 있음). 크기 1로 정규화
  material: { type: 'MeshPhysicalMaterial' | 'MeshStandardMaterial', params: {...}, renderOrder },
  deform: [patch],   // 꼭짓점 조각(shaderPatches.js 조각 형식). 박동·헤엄
  shade:  [patch],   // 프래그먼트 조각. 림 발광, (해파리) 프레넬 불투명도
  cpu:    { pulse? },
  info:   { triangles, unit, origin, front, up },
}
```

### 2.2 지오메트리 속성

| 속성 | 크기 | 뜻 |
|---|---|---|
| `position`, `normal`, `color` | 3 | `color`는 꼭짓점 색(선형) → 재질에 `vertexColors: true` |
| `aDef` | 4 | `render/core/deform.js` 규칙과 같음. x = 몸 길이 방향 s, y = 마스크, z = 부위 번호, w = 부위 안 번호 |
| `aMat` | 2 | 새로 넣음. x = 불투명도 배율(반투명 종), y = 발광 더하기(눈 반짝임·감각곤) |

몸 규칙은 P1과 같아요: 앞 +Z, 위 +Y. 물고기는 몸길이 1·원점 몸 중심, 해파리는 갓 지름 1·원점 갓 가장자리 평면 중심.

부위 번호

| 종 | z = 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 해파리 | 갓 바깥면 | 갓 안쪽면·생식소 | 가장자리 촉수 | 입팔 | 감각곤 |
| 물고기 | 몸 | 등·뒷·꼬리지느러미 | 가슴지느러미(w = 좌우) | 배지느러미(w = 좌우) | 눈 |

### 2.3 재질 조립(이 순서로)

```js
import { kitMaterial } from '../render/aqua/school.js';
const material = kitMaterial(kit);   // 기본 slots ['medium'], defines { OW_CAUSTICS: true }
const sm = new SpeciesMesh(kit.geometry, material, count);   // render/core/instancing.js 그대로
sm.mesh.renderOrder = kit.material.renderOrder;
```

`kitMaterial` 안에서 하는 일: `new THREE[type]({ vertexColors: true, ...params })` → `patchMaterial(m, [DEF_COMMON, SQUASH, ...kit.deform, ...kit.shade], { slots, defines })`.

- `DEF_COMMON`(공용 선언)이 반드시 먼저예요. 조각들이 `aDef`·`aPhase`·`aSpeed`·`aParams`·`uDeformGain`·`uCurrent`·`owRot`을 씀.
- `SQUASH`가 들어가 있어 블록 젤리 눌림(`uSquash`)과 개체 출렁(`aParams.w`)에 같이 출렁여요(P1과 같음).
- P1의 `RIM` 조각은 넣지 않아요. 림 발광은 생성기 `shade`가 화풍마다 다르게 가져요.
- 인스턴스 속성: `aSpeed` = 헤엄·박동 박자 배율(P1처럼 속도에 맞춰 갱신), `aPhase` = 개체 위상. 그 밖의 `aParams`는 P1과 같은 뜻(y = 걷는 중, w = 출렁 세기).
- `kitMaterial`을 `render/aqua/school.js`에 둔 것은 맡은 파일 안에 두려는 임시 자리예요. 결합할 때 `render/core/`(예: `instancing.js` 옆)로 옮기는 게 맞아요. core가 aqua를 import하면 안 되므로요(PLAN 3절).

### 2.4 장식 떼

```js
import { createSchool } from '../render/aqua/school.js';
import * as chromis from '../eco/atoll/species/chromis.js';
const school = createSchool(chromis.build(THREE, { variant }), {
  schools: [{ count: 46, center: [x, y, z], radius: [rx, ry, rz], speed: 1.5, spread: 1.15, size: 0.42 }, ...],
  bounds,            // THREE.Box3(부모 좌표) — 블록 물 상자
  floor: (x, z) => y // 바닥 높이(부모 좌표). 게임에서는 coords + heightAt로 만들어 넘김
});
world.add(school.mesh);
app.onUpdate((dt, t) => school.update(dt, t));
```

- 떼마다 매끈한 궤도 하나(리사주)를 돌리고, 물고기마다 궤도를 조금 늦게 따라가며 떼 안의 제자리에서 흔들려요. 규칙(`sim/`)과는 아무것도 주고받지 않아요.
- 바닥 아래로는 내려가지 않지만, 지형 기둥·섬을 피하지는 않아요(갤러리 바닥은 평평). 게임에서는 궤도 중심을 칸두·석호의 열린 물 위에 두면 돼요 [추정].

## 3. 샘플과 화풍별 장단점

그림: `p3-compare-moonjelly.jpg`, `p3-compare-clownfish.jpg`, `p3-compare-clownfish-front.jpg`, `p3-lineup-front.jpg`, `p3-lineup-high.jpg`

### 3.1 보름달물해파리

| | P1 임시 도형 | A 매끈한 젤리풍 | B 그래픽 로우폴리풍 |
|---|---|---|---|
| 갓 | 높은 반구 | 납작한 접시, 가장자리 8곳 홈 | 16조각 각진 접시, 8곳을 당겨 별 모양 |
| 생식소 | 분홍 점 무늬(색칠) | 연분홍·보라 네 잎 클로버(입체 고리) | 진분홍 각진 고리 |
| 촉수 | 길고 굵은 24가닥 + 입팔 4 | 짧고 가는 술 72가닥 + 주름 입팔 4 + 감각곤 8 | 세모 기둥 16가닥 + 지그재그 입팔 4 |
| 삼각형(몸 1개) | 2,112 | **10,256** | **688** |
| 재질 | Physical, 프레넬 불투명도 | Physical + 무지갯빛(iridescence)·광택(sheen), 프레넬 불투명도 | Standard, 면 음영, 불투명도 조금 높게 |

- A 장점: 실제 보름달물해파리처럼 보여요(납작한 갓, 클로버 생식소, 짧은 술). 가까이서 가장 "젤리"다워요. 단점: 삼각형이 많아요(7마리 × 2패스 = 약 14만 개). 가는 술은 먼 시점에서 거의 안 보여요. 갓의 방사관 무늬는 어느 각도에서도 잘 안 보였어요 [확인: `p3-lineup-high.jpg`].
- B 장점: 가볍고(A의 1/15), 생식소가 진해서 작게 보여도 종이 읽혀요. 다른 로우폴리 지형·물건(P1 물건이 면 음영)과 잘 어울려요. 단점: 각진 갓은 "말랑한 젤리"보다 "유리 공예"에 가까워 보여요.

### 3.2 몰디브흰동가리

| | P1 임시 도형 | A 매끈한 젤리풍 | B 그래픽 로우폴리풍 |
|---|---|---|---|
| 무늬 | 흰 띠 3줄(일반 흰동가리) | **흰 머리 띠 1줄 + 검은 테**(몰디브흰동가리 그대로) | 같음, 테두리가 칼같이 또렷 |
| 지느러미 | 판 2장 | 톱니 등지느러미·둥근 꼬리·검은 배·뒷지느러미·젓는 가슴지느러미 | 같은 구성을 삼각형 몇 개로 |
| 눈 | 검은 구슬 2개(몸 밖으로 튀어나옴) | 큰 검은 눈동자 + 금빛 테 + 반짝임 | 검은 팔면체 + 흰 반짝임 |
| 삼각형 | 1,016 | **3,528** | **238** |

- A 장점: 광택 있는 "젤리 사탕" 느낌이 가장 강하고 표정이 귀여워요. 단점: 몸이 매끈해서 P1 물건(면 음영)과 질감이 달라요.
- B 장점: 무늬 경계가 또렷해 멀리서도 종이 읽혀요. 아주 가벼워요. 단점: 광택이 약해 "젤리" 정체성은 A보다 덜해요.

### 3.3 장식 떼(푸른자리돔)

연한 청록 몸, 깊게 갈라진 꼬리. 몸 1개 삼각형 A 382 / B 96. 갤러리에서 떼 2개 76마리 [확인: `p3-crowd-*.jpg`]. 크기 0.4칸 안팎이라 두 화풍 차이는 거의 안 보여요.

### 3.4 실제 종과 너무 다르지 않은지(게임적 허용 안의 판단)

| 종 | 실제와 맞춘 것 | 일부러 바꾼 것(게임적 허용) | 판단 |
|---|---|---|---|
| 보름달물해파리 | 납작한 갓, 네 잎 생식소, 가장자리 홈·감각곤, 짧은 술, 주름 입팔 | 촉수를 조금 길고 굵게, 생식소 색을 진하게 | 실제 종으로 읽힘. P1의 높은 반구·긴 촉수는 오히려 다른 해파리(예: 해파리 일반)처럼 보였음 |
| 몰디브흰동가리 | 흰 머리 띠 하나, 주황 몸, 검은 배·뒷지느러미(학명 nigripes = 검은 발), 둥근 꼬리 | 눈을 크게, 띠를 조금 넓게, 지느러미를 조금 크게 | 실제 종으로 읽힘. P1의 세 줄 띠는 다른 흰동가리 종 무늬였음 |
| 푸른자리돔 | 청록 몸, 갈라진 꼬리, 큰 무리 | 몸빛을 조금 밝게 | 문제 없음 |

종의 생김새는 제가 아는 일반 지식으로 맞췄고, 이번에 사진 자료를 다시 찾아 대조하지는 않았어요 [추정].

## 5. 드로우콜·삼각형

### 5.1 갤러리에서 잰 값 [확인]

| 구성 | 드로우콜 | 삼각형(그린 패스 합) |
|---|---|---|
| 해파리 1종(InstancedMesh 1개) | **2** | A 7마리 143,584 · B 7마리 9,632 · P1 7마리 29,568 |
| 흰동가리 1종 | **1** | A 10마리 35,280 · B 10마리 2,380 · P1 10마리 10,160 |
| 장식 떼 76마리 | **1** | A 29,032 · B 7,296 |

해파리가 2회인 까닭: 반투명 + 양면 재질은 three가 뒷면·앞면을 두 번 나눠 그려요(P1 해파리도 2회). 삼각형도 두 번 세요. 1회로 줄이려면 재질에 `forceSinglePass: true`를 주면 되는데, 뒷면·앞면 겹침 순서가 달라져 모양을 다시 봐야 해요 [추정].

### 5.2 게임에 붙였을 때 [추정]

- 종 메시는 P1과 같은 방식(종마다 InstancedMesh 1개)이라 **생물 쪽 드로우콜은 늘지 않아요.** 장식 떼가 1회(떼 종을 둘로 하면 2회) 늘어요. P1 결산의 19회 → **20~21회**로, 목표(PLAN D8 프레임당 300회 이하)에 한참 못 미쳐요.
- 삼각형은 P1 기준 약 22.6만 개에서: A로 8종을 모두 만들면 해파리만 +11만, 흰동가리 +2.5만, 떼 +2.9만 → 약 39만 개(조사 문서 목표 50만 이하 안쪽이지만 나머지 6종에 따라 넘을 수 있음). B는 약 20만 개로 오히려 줄어요.
- A로 간다면 `detail`을 먼 시점에서 낮추거나, 해파리 술 수를 줄이는 손잡이가 있어요(지금 72가닥).

### 5.3 프레임 속도

**재지 못했어요.** 내장 브라우저 창이 가려진 상태여서 화면 갱신이 멈춰 fps 표시가 비어 있었어요. 갤러리 왼쪽 위에 fps·드로우콜·삼각형이 나오니, 대니님이 직접 열어 보시면 바로 보여요.

> **어느 화풍으로 8종·18종을 만들까요?**
