## 1. 조사에서 나온 핵심 사실

근거 표기는 각 조사 문서에 있어요. 여기서는 결정에 영향을 주는 것만 적어요.

**직접 확인된 것**

- 참고 사례는 Three.js r170 + WebGL2, 에셋 파일 0개, 빌드 도구 없음. 최신 Three.js(0.187.0)로 돌려도 경고 2개뿐이에요.
- 참고 사례의 젤리 출렁임은 월드 행렬 하나에 감쇠 스프링 값을 넣는 방식이라 비용이 거의 없어요.
- 참고 사례는 물에 투과(transmission) 재질을 써요. 그 결과 **물속 물고기 색이 청록·남색으로 죽고, 반투명 물체가 보이지 않고, 드로우콜(GPU 그리기 요청) 1,289회 중 432회가 여기서 나와요.** 물속이 주인공인 우리 게임에는 그대로 쓸 수 없어요.
- 인스턴싱(같은 메시를 한 번에 여러 개 그리기) + 꼭짓점 셰이더 변형으로 해파리 200마리 박동이 드로우 1회에 그려져요(정지 화면 한 장으로 확인).
- WebGPU 렌더러는 참고 사례의 핵심 기법(셰이더 조각 주입)을 지원하지 않아요.
- sand3d는 AI 생성 모델이 아니라 Blender 위의 Python 모델링 라이브러리(Apache-2.0)예요. 뼈대 리깅이 없어 헤엄 동작에는 못 써요.
- 무료 에셋: Quaternius는 2026-08-28에 재배포 금지 라이선스로 바뀜, Poly Haven은 실사풍에 산 생물 없음, Sketchfab은 대부분 CC-BY·비상업 혼재. Hunyuan3D는 라이선스가 대한민국에 적용되지 않아요.
- 납작한 블록(40×40, 높이 15)은 어느 각도에서 봐도 화면에 비치는 면적이 위에서 본 면적 이하예요. 수직축은 몸이 부딪히지 않는 여유는 주지만 화면에서 흩어져 보이는 효과는 작아요.

**아직 만들어 보지 않은 제안**(시제품에서 확인해야 함)

- 투과 없이 물 덩어리를 그리는 방법(물속 거리 안개 + 뒷면 물색 + 앞면 광택)
- 섬과 해저를 높이 함수 하나로 만들고 셰이더가 수위로 물 위·아래를 나누는 방법
- 열대 물빛 식, 수면 경계 처리, 생태계별 물 프로필
- `BatchedMesh`(서로 다른 메시를 한 번에 그리는 기능)에 셰이더 조각 주입이 되는지
- 노트북에서의 실제 프레임 속도(원격 환경은 소프트웨어 GPU라 잴 수 없음)

## 3. 아키텍처

```
games/ocean-world-3d/
  index.html  manifest.webmanifest  sw.js  icons/
  vendor/three-0.187.0/          Three.js 원본 파일(고치지 않음)
  sim/                           규칙. 화면 없음, Node 테스트, 고정 시간 단계 1/30초, 시드 난수
    rules.js                       경제·한도·발전도·행복도·요청·포착
    space.js                       격자, 구역(육지·해저·수중 층), 놓기 판정
    move.js                        생활형별 이동(바닥 길찾기, 유영 조향, 표류, 수면 오가기)
    save.js                        저장 형식
  eco/atoll/                     생태계 데이터(열대 환초)
    data.js                        생물·물건·수치(sim이 읽음)
    terrain.js                     지형 정의 한 곳(sim은 격자로, 렌더는 높이 함수로 읽음)
    profile.js                     빛·물빛 값 묶음
    species/  props/               생물·물건 생성기(렌더가 읽음)
  render/core/                   3D 기반. 생태계와 무관(Animal World 다음 버전도 씀)
    app, stage, camera, jelly, terrain, materials(shaderPatches), instancing, deform, labels, picking, capture
  render/aqua/                   물이 있는 생태계 전용
    heightfield, surface, waterFog, caustics, swim, buoyancy, particles
  ui/                            HUD, 패널, 놓기 흐름(DOM)
  test/  tools/                  규칙 테스트, 밸런스 봇, 생성기 점검표, 성능 측정 페이지
  docs/
```

지켜야 할 경계

| 규칙 | 이유 |
|---|---|
| `sim/`은 Three.js와 DOM을 import하지 않아요 | Node에서 테스트·봇이 돌아야 해요(Animal World `logic.js`와 같은 방침) |
| 생물 위치·상태는 `sim/`이 정하고, 렌더는 그리기만 해요. 출렁임·헤엄 변형·장식 물고기 떼는 렌더 쪽 연출이에요 | 규칙이 화면 속도와 무관하게 같아야 해요 |
| `render/core/`는 `render/aqua/`를 import하지 않아요. aqua가 core의 확장점(셰이더 조각 슬롯, 시뮬레이션 훅)에 끼워 넣어요 | 육지 생태계를 올릴 때 core를 그대로 쓰려고 |
| 지형 정의는 `eco/<생태계>/terrain.js` 한 곳이에요 | 규칙의 격자와 화면의 지형이 어긋나지 않게 |
| 셰이더 조각 주입은 `materials/shaderPatches.js` 한 곳에 모아요 | 나중에 WebGPU(TSL)로 옮길 때 고칠 곳을 한 곳으로 |

조사 문서 두 곳의 폴더 이름이 서로 달라서(`core/`가 한쪽은 규칙, 한쪽은 렌더 기반) 위처럼 `sim/`과 `render/core/`로 정리했어요.

지금 하지 않는 것: 걷는 동물, 육지 길찾기, 낮밤 조명 보간. 경계만 나눠 두고, Animal World 다음 버전을 시작할 때 만들어요.

### 4.1.1 P1 진행 기록

### 4.2 위임 규칙

- 하위 세션은 opus 5.5, high effort로 띄워요.
- 하위 세션마다 브랜치 하나(`claude/ocean-world-3d-<작업>`)와 맡은 폴더가 있어요. 맡지 않은 폴더는 고치지 않아요.
- 동시에 도는 하위 세션이 같은 파일을 건드리지 않게, 맞닿는 부분(예: 규칙이 화면에 넘기는 상태의 모양)은 메인 세션이 먼저 문서로 정해서 넘겨요.
- 하위 세션은 PR을 만들지 않아요. 메인 세션이 브랜치를 받아 직접 읽고, 테스트와 녹화 모드 화면으로 확인한 뒤 통합 브랜치에 합쳐요.
- 하위 세션의 보고는 근거로 쓰되 그대로 믿지 않아요. "확인함"과 "추정"을 구분해 보고하게 하고, 핵심 사실은 메인 세션이 다시 대조해요.
- `main`에 합치는 것은 단계가 끝날 때 대니님이 요청하면 해요.

### 4.3 P1에서 두 하위 세션이 맞닿는 부분

P1은 시제품(화면)과 규칙 기반을 동시에 만들고, P2에서 잇는다. 그래서 둘이 같은 파일을 고치지 않게 아래처럼 나눈다.

| | 시제품 세션(`claude/ocean-world-3d-p1-proto`) | 규칙 세션(`claude/ocean-world-3d-p1-sim`) |
|---|---|---|
| 맡은 곳 | `index.html`, `vendor/`, `render/`, `eco/atoll/terrain.js`, `eco/atoll/profile.js`, `tools/capture*`, `docs/p1-proto-report.md`, `docs/img/p1/` | `sim/`, `eco/atoll/data.js`, `test/`, `tools/sim.js`, `package.json`, `DESIGN.md`(결정 반영), `docs/p1-sim-report.md` |
| 생물 움직임 | 화면 확인용 임시 움직임(렌더 안에서 떠다니기) | 규칙으로 정하는 실제 움직임 |
| 지형 | 실제 환초 지형 정의를 만든다 | 임시 격자(`test/fixtures/`)로 개발한다 |

지형 약속(`eco/atoll/terrain.js`, Three.js·DOM을 import하지 않는 순수 함수 모듈)

```js
export const GRID = { w: 40, h: 40 };        // 본 블록 칸 수(x, y)
export const EXT  = { side: '+y', depth: 20 }; // T8 확장 영역: 어느 옆면에, 몇 칸 깊이로(폭은 GRID.w)
export const SEA_LEVEL = 0;                   // 수면 높이(칸 단위). 바닥은 음수, 섬은 양수
export const MAX_DEPTH = 12;                  // 가장 깊은 곳(칸)
export function heightAt(x, y)                // 연속 좌표(칸 단위) → 높이(칸 단위). 화면용
export function kindAt(cx, cy)                // 칸 → 'island'|'beach'|'lagoon'|'reefflat'|'thila'|'kandu'|'slope'|'dropoff'|'void'
export function cellHeight(cx, cy)            // 칸 → 규칙용 높이(1/3칸 단위 정수)
```

- 좌표: 격자 (x, y)는 바닥면, z는 높이(위가 +). 렌더는 Three.js 좌표로 바꿔 쓴다(변환은 `render/core/`의 한 곳에서).
- 규칙은 `eco` 객체(지형 함수, 생물·물건 데이터, 경제 수치)를 인자로 받는다. 생태계 이름이나 바다 전용 가정을 `sim/` 안에 박아 넣지 않는다.
- 규칙이 화면에 넘길 상태의 모양(P2에서 사용): 생물마다 `{ uid, sp, x, y, z, face, st, ph }`, 물건마다 `{ uid, id, x, y, zone, layer }`. 규칙 세션이 `docs/p1-sim-report.md`에 확정 형태를 적는다.
