# My Little Cafe — 기획

2026-11-05 대니님과 아이디어 회의로 정했어요. 지금은 **스토리 모드와 두 카페의 봄 20일 본게임**까지 구현했어요. 여름 이후와 가게 확장은 다음 단계예요.

세로 화면 모바일 웹 게임이에요. 스트레스에 지친 30대 중반 대기업 과장이 은퇴를 앞둔 사장님의 개인 카페를 물려받아요. 커피를 전혀 몰라도 할 수 있게, 튜토리얼이 곧 스토리 모드예요.

## 1. 대니님 확정 사항

| 항목 | 내용 |
|---|---|
| 제목 | My Little Cafe |
| 구조 | 스토리 모드(튜토리얼) → 끝내면 본게임이 열림 |
| 시작 선택 4가지 | 주인공 남/여(30대 중반) · 기존 오너 남/여(60대 중반, 경력 30년) · 카페 오피스/주택가(둘 다 개인 카페) · 카페 이름(제공 5개 또는 직접 입력) |
| 중심 대사 | "나도 자네 나이에 커피를 시작했다네." |
| 문구 | '합니다'체 금지, 자연스러운 구어체. 시스템은 해요체, 오너는 "자네"와 "-네/-게", 주인공은 존댓말 |
| 오피스 프롤로그 | 점심 먹으러 가는 식당가 골목 안의 카페 |
| 주택가 프롤로그 | 주말 오전에 느긋하게 들르는 동네 카페 |
| 오피스의 재미 | 빠른 손놀림, 정확한 제조, 경영 |
| 주택가의 재미 | 단골에 맞춘 테이스트, 커피 자체의 특색, 카페 분위기 |
| 완료 기준 | 대니님이 외부 설명 없이 게임 안내만 보고 스토리 모드를 끝낼 수 있어요 |

제목·이름·오피스 위치 해석: 오피스 카페는 **회사 근처 오피스빌딩 1층, 식당가 골목 쪽 입구**로 해석했어요.

## 2. 튜토리얼 원칙

- 처음엔 오너가 대부분 대신하고, 플레이어가 맡는 일이 하나씩 늘어나요.
- 쉬운 말을 먼저 쓰고 용어는 괄호로 알려 줘요: "꾹 눌러 다지기(탬핑)".
- 숫자를 외우지 않아도 되게 게이지의 초록 칸에 맞춰요.
- 맛은 `시큼 ←●→ 씀` 저울 한 줄로 보여 줘요. 시큼하면 곱게, 쓰면 굵게.
- 일부러 실패한 잔을 맛보게 하고 이유와 고칠 방법을 바로 알려 줘요.
- 스토리 모드에서 실패는 불이익이 없어요. 5일차 시험만 다시 해야 할 수 있어요.
- 배운 내용은 커피 노트에 저절로 쌓이고 언제든 다시 볼 수 있어요.

## 3. 스토리 모드

| 날 | 배우는 것 | 오너가 대신하는 것 |
|---|---|---|
| 프롤로그 | 카페와의 만남(위치별), 폐업 안내, 결심 | 건너뛰기 가능 |
| 1일차 | 샷 멈추기 → 담기·다지기 → 분쇄 | 처음엔 추출 외 전부, 마지막엔 없음 |
| 2일차 | 맛 고치기, 아메리카노, 첫 단골 | 맛 판단을 도와줘요 |
| 3일차 | 우유 스팀, 라떼, 메뉴 구분 | 온도 알림 |
| 4일차 | 사장님의 오후 수업: 핸드드립 | 뜸 들이는 시간 알림 |
| 5일차 | 혼자 하는 하루. 오피스는 평일 점심 러시(별 8개 이상, 오래 기다린 손님 2명 이하), 주택가는 주말 오전 단골 취향 맞히기(별 5개 이상) | 없음 |
| 엔딩 | 열쇠와 노트, 선반의 사이펀, 후배에게 내리는 드립, 처음 듣는 "사장님" | |

요일: 오피스는 1일차 월요일, 5일차 금요일. 주택가는 1일차 화요일, 5일차 토요일이에요.

엔딩 뒤 타이틀의 본게임은 1단계에서 "준비 중"이에요. 스토리 건너뛰기는 본게임이 생기는 2단계에서 넣어요.

## 4. 제조 규칙

수치는 실제 레시피를 기준값으로 썼어요. 정답이 아니라 게임의 기준이에요.

| 메뉴 | 기준 | 게임 시간 | 근거 |
|---|---|---|---|
| 에스프레소 | 18g → 36g, 25~30초 | 약 8초(실제 초 표시) | Clive Coffee |
| 아메리카노 | 샷 + 뜨거운 물 | 약 3초 | 게임 규칙 |
| 라떼 | 샷 + 스팀 우유 60~65℃, 공기는 짧게 넣고 소용돌이로 데우기 | 약 8초 | Clive Coffee |
| 핸드드립 | 20g + 물 320g(1:16), 뜸 물 40g·30초, 전체 약 3분 | 약 35초 | 판매점·로스터리 안내 여러 곳 |

맛 규칙은 하나예요. **접촉 시간이 짧거나 추출량이 적으면 시큼하고, 길거나 많으면 써요.** 분쇄가 굵으면 물이 빨리 빠져 시큼해지고, 고우면 천천히 빠져 써져요. 다지기가 비뚤거나 물을 고르게 붓지 않으면 맛이 탁해져요(균일도 점수).

정답 분쇄는 날마다 조금씩 달라요. 실제로 원두와 날씨에 따라 다시 맞추는 일(다이얼인)을 게임으로 만든 거예요.

### 5.1 점수: 별은 커피로만 (2026-11-05 대니님 확정)

속도 점수를 높게 잡으면 커피 게임에서 벗어나므로, 첫 제안(오피스 속도 40·정확도 40)을 버렸어요.

| | 오피스 | 주택가 |
|---|---|---|
| 별 기준 | 맛과 제조 품질 | 맛과 제조 품질(단골은 그 사람 입맛 기준) |
| 추가 보상 | 빨리 내면 팁과 다음 손님 | 입맛을 맞히면 단골과 더 친해짐 |
| 못했을 때 | 늦으면 손님이 떠나 매출이 줄어요 | 입맛이 빗나가면 단골이 덜 찾아와요 |

오피스의 핵심 실력은 **바쁠 때도 맛을 지키는 것**이에요. 스토리 러시 시험도 같은 원칙이라 늦어도 별을 깎지 않고, 합격 조건에서 오래 기다린 손님 수를 따로 봐요.

| | 오피스 | 주택가 |
|---|---|---|
| 기본 메뉴 | 에스프레소, 아메리카노, 라떼 | 에스프레소, 아메리카노, 라떼, 핸드드립 |

두 카페 모두 테이크아웃과 매장 손님을 받아요. 베이글과 구움과자는 게임 컨셉에 꼭 필요하지 않아 빼서, 메뉴는 커피로만 채워요. 비율과 좌석 수는 첫 제안이라 봇으로 맞춰요. 콜드브루와 아이스 음료 레시피는 구현 전에 조사해요.

### 5.2.1 저장과 모드 (2026-11-05 대니님 확정)

스토리 모드는 공통이고 이어 하기 하나로 진행해요. 스토리를 끝내면 **오피스 가게와 동네 가게가 함께 열려요.** 가게마다 저장을 따로 두고, 한쪽을 끝내지 않아도 언제든 오갈 수 있어요. 플레이어의 자유를 최대한 보장하려는 거예요.

주인공과 사장님은 스토리 설정을 그대로 쓰고, 스토리에서 고르지 않은 쪽 가게는 처음 열 때 이름만 정해요. 스토리를 다시 해도 가게 기록은 지워지지 않아요. 가게 기록은 ↺ 버튼으로 그 가게만 지울 수 있어요.

### 5.3 영업시간 (2026-11-05 대니님 확정)

두 카페 모두 **오전 8시부터 저녁 8시까지 12시간** 영업해요. 그동안 주인이 계속 근무해요. 알바를 둘지는 나중에 판단해요. 그래서 2단계 범위에서 알바를 뺐어요.

### 5.4 본게임의 시간과 모드 (2026-11-05 대니님 확정)

| 모드 | 화면 | 시간 | 누구를 |
|---|---|---|---|
| 메인 모드 | 점내 장면 | 흘러요. 12시간이 약 5분 | 일반 손님 |
| 대화 모드 | 스토리와 같은 바 화면 | 멈춰요 | 단골 |

단골은 오피스와 주택가 **둘 다** 있어요. 하루 평균 **20잔 내외**를 목표로 해요(2026-11-05 대니님). 5분은 300초라 평균 15초에 한 잔꼴인데, 지금 같은 라떼 제조(약 25~30초)로는 하루 10~12잔밖에 못 만들어요. 그래서 메인 모드의 조작을 줄여요(5.7절).

**나중에 설계할 점:** 실제 카페라면 하루 100잔쯤 팔아야 해요. 20잔으로도 수익이 나도록 월세와 원가, 메뉴 가격을 게임에 맞게 조정해요.

### 5.5 가게 외관과 점내 (2026-11-05 대니님 확정)

- 스토리 대화 화면은 그대로 두고, 그 사이에 가게 앞과 가게 안 장면을 넣어요. 손님이 들고 나는 모습과 내 가게 모습을 보여 줘요.
- **테이크아웃 손님도 매장 손님처럼 들어와 카운터에서 주문해요.** 주문 뒤에 나가느냐 앉느냐만 달라요.
- 동선 규칙은 `floor.js`, 그림은 `art-shop.js`예요. 오피스는 좁고 깊게(창가 바 4석 + 2인 테이블 2개), 주택가는 넓게(4인 테이블 4개) 배치했어요.

### 5.6 날씨, 계절, 1년 (2026-11-05 대니님 확정)

- 날씨와 계절 요소를 넣어요. 하루는 실시간 5분, **계절 하나는 20일**, 1년은 4계절이에요.
- 계절 하나는 100~120분, 1년은 최대 약 8시간이에요(순수 영업만 치면 400분).
- 그사이 가게를 **확장할 수도, 안 할 수도** 있어요. 확장은 선택이에요.
- **소나기(여름 한정, 대니님 확정):** 일시적이에요. 랜덤한 시간 동안만 내리고 하루 종일 지속되지 않아요. 그친 뒤 날씨는 맑음이고, 하루 1회까지만 내려요. 여름을 만들 때 구현해요.
- **결산:** 계절이 끝날 때마다, 즉 20일에 한 번(1년에 4번) 해요. 요일은 7일 주기로 돌려요.
- **시작:** 봄부터 시작해요. **봄 20일을 먼저 만들어 재미를 확인**한 뒤 나머지 계절로 넓혀요.
- **1년 뒤(제안):** 연말 결산과 평가로 엔딩을 보여 주고, 원하면 2년 차를 이어 가요. 세부 내용은 나중에 정해요.

### 5.7 메인 모드의 조작 (2026-11-05 대니님 확정)

단순한 메뉴까지 매번 전부 만들면 금방 지루해져요. 그래서 메뉴별로 조작을 나누고, 자동화를 성장 보상으로 줘요.

| 단골의 한 잔 | 전부 직접 | 멈춤 |

- 자동 잔의 맛은 **아침에 맞춘 분쇄 칸**으로 정해져요. 별은 커피로만 준다는 원칙(5.1절)이 그대로예요.
- 자동 잔은 편하지만 맛이 최고점까지 오르지는 않아요. 바쁠 때는 자동, 여유가 있으면 직접 만드는 선택이 생겨요.
- 성장(첫 제안): 시작은 아메리카노만 자동 → 그라인더를 사면 담기 자동 → 머신을 올리면 샷 2잔 동시 → 스팀 숙련으로 라떼 자동 가능(직접 치면 별과 팁이 더 붙어요).
- 하루 구성 계산(첫 제안): 자동 13잔 52초 + 라떼 4잔 48초 + 드립 1잔 35초 + 단골 2잔(시간 멈춤) = 약 135초. 300초 중 나머지는 주문받기와 내주기, 러시 여유예요.

### 5.8 서브제품 (2026-11-05 대니님 확정)

매출과 순이익을 맞추려고 디저트와 원두를 함께 팔아요. 앞선 "베이글·구움과자 제외"와 "손님이 원두를 주문"을 이 내용으로 대체해요.

| | 디저트 | 원두 200g |
|---|---|---|
| 들여오기 | **외부에서 공급**받아요. 아침에 수량을 정해요 | **직접 로스팅**해요. 아침에 온도를 보고 꺼내요 |
| 남으면 | 저녁에 버려요 | 남겨 두고 팔아요 |
| 값(첫 제안) | 원가 2,000원, 판매 4,500원 | 8봉지에 48,000원, 판매 16,000원 |

커피를 산 손님이 일정 확률로 함께 사요. 확률은 변수의 곱이에요: 카페 위치, 평판, 그 잔의 별, 단골과의 친밀도, 시간대·날씨(디저트), 로스팅 품질·주말(원두). **가게를 잘 운영할수록 많이 팔리는 구조예요.**

### 5.9 랜덤 이벤트 (2026-11-05 대니님 아이디어, 나중에 구현)

본게임에 랜덤 이벤트를 넣는 걸 나중에 검토해요. 대화 모드로 나오면 시간이 멈춰서 기존 구조에 잘 맞아요.

- **진상 손님:** 심리적으로 힘들어하면서 "괜히 회사 그만뒀나" 하고 눈물을 찔끔 흘려요.
- **심쿵 손님:** 잘생긴 손님이나 예쁜 손님이 들어와 설레요.

### 5.10 그림 방향 (2026-11-05 대니님 결정)

스토리와 단골 대화는 **이미지 모델로 만든 배경과 인물을 겹치는 방식**(비주얼 노벨 구조)으로 바꿨어요. 화면 구조는 그대로예요. 그림체는 **사실적인 일본 애니메이션 영화풍**이고, 프롬프트에는 작가 이름 없이 빛, 하늘, 채색 같은 특징만 적어요.

쿼터뷰와 제조 화면이 너무 달라 보이지 않게(대니님 지적) 다음처럼 맞췄어요.

| 화면 | 그림 파일 | 코드로 그리는 것 |
|---|---|---|
| 스토리·단골 대화 | 배경(카페 2곳 × 맑음·흐림·비), 인물 표정, 가게 앞(낮·밤), 이야기 장면 | 카페 이름, 안내문 글자, 비 줄기 |
| 쿼터뷰 메인 | 방(코드 배치도를 참고해 다시 그려 좌석 좌표가 맞아요) | 걷는 손님 |
| 제조 | 벽·카운터, 그라인더, 머신, 포터필터, 탬퍼, 주전자, 드리퍼, 로스터 | 다이얼, 게이지, 커피·물·우유, 원두 층 |

소나기는 비 배경을, 눈은 겨울을 만들 때 그릴 배경을 써요. 걷는 손님은 프레임 일관성 문제로 코드 그림에 외곽선을 더해 맞췄어요. 모델은 `google/gemini-3-pro-image`, 파일은 WebP예요.

## 6. 선행조사 기록

- **채택:** 저장소의 기존 방식(바닐라 JS, `logic.js` 분리 테스트, 캔버스 그림, Web Audio 합성, 네트워크 우선 서비스 워커). 레시피는 [Clive Coffee 에스프레소](https://clivecoffee.com/blogs/learn/the-perfect-espresso-recipe), [Clive Coffee 우유 스팀](https://clivecoffee.com/blogs/learn/how-to-steam-milk-for-lattes-and-cappuccinos-at-home-clive-coffee), [Seattle Coffee Gear 드립](https://www.seattlecoffeegear.com/blogs/learning-center/how-to-dial-in-pour-over).
- **기각:** COREVIS Library 자료. 게임 이펙트가 도트 스타일이라 맞지 않고, 공개 저장소 커밋이 재배포에 해당하는지 불명확해요. 우유 유체 시뮬레이션과 라떼아트는 위험이 커서 후속으로 미뤘어요.
- **로스팅:** 1차 크랙 약 196~205℃, 중간 로스팅 약 210~220℃로 출처들이 모여요. [Coffee Roast Co.](https://coffeeroastco.com/blogs/coffee-roast-co-blog/the-coffee-roasting-process), [Aromatico](https://aromatico.de/en/e/coffeeroasting). 로스터와 측정 방식에 따라 달라서 게임 기준값으로만 써요.
- **주의:** 드립 수치는 출처마다 조금 달라요. 카페 이름 뜻풀이는 표준국어대사전으로 확인했어요. `온새미로`는 표제어가 없어 `온새미`의 뜻으로 설명해요.
