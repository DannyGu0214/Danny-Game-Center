# 퀴즈퀴즈 2026 — 게임 설계안

2026-11-13에 첫 설계안을 썼고, 같은 날 대니님 답으로 팀 구조, 기회 규칙, 분위기, 배포 조건을 정했어요. 아직 코드는 없어요. **대니님이 정한 것**과 **첫 제안**(Claude)을 나눠 적었어요. 첫 제안은 대니님이 확정하면 날짜와 함께 "대니님 확정"으로 바꿔요.

초등학생부터 중학생 눈높이의 퀴즈 대항전이에요. 90년대 TV 가족 예능 같은 도트 무대에서 A팀과 B팀이 6분야 문제로 겨뤄요. 어른이 같이 해도 재밌게 만들어요.

## 1. 대니님 확정 사항 (2026-11-13)

| 항목 | 내용 |
|---|---|
| 제목 | 퀴즈퀴즈 2026. 영문 표기와 폴더는 `quiz-quiz-2026`. 넥슨 '퀴즈퀴즈'(1999)와 이름이 겹치는 걸 알고 정했어요 |
| 대상 | 초등~중학생 눈높이의 한국 학생. 어른이 풀어도 재밌게 |
| 팀 | 게임에는 늘 **A팀과 B팀** 두 팀이 나와요. 한 팀은 2명이 **하나로** 문제를 풀고, 그림도 둘을 한 단위로 그려요(예: 키 큰 애와 작은 애 친구, 남자애와 여자애 남매) |
| 혼자 할 때 | 내가 한 팀, 컴퓨터가 다른 팀이에요. **컴퓨터가 너무 잘하면 안 돼요** |
| 둘이 할 때 | 한 사람씩 A팀과 B팀을 맡아요. 가로 화면이에요 |
| 기회 규칙 | 한 팀이 못 맞히면 기회가 다른 팀으로 넘어가요. 그 팀도 못 맞히면 두 팀에 한 번씩 더 기회를 줘요. **나중에 바뀔 수 있어요** |
| 분위기 | 진중한 퀴즈쇼가 아니라 초등학생 눈높이의 **밝은 B급 병맛**이에요. 90년대 가족 오락 예능 같은 레트로 분위기, 진행자 커플과 도우미 같은 여러 캐릭터 |
| 그림 | 도트 그래픽. 세련되게 |
| 문제 | 고퀄. 허투루 내지 않아요. 문제은행에 등급을 나누는 장치가 있어야 해요 |
| 분야 | 과학, 역사, 지리, 예술, 일반상식, 넌센스 (6개) |
| 형식 | 주관식과 4지선다 둘 다 |
| 재료 | 공공기관과 선생님들이 만든 교과 콘텐츠(대니님 조사 목록, 10.8절) |
| 배포 | 상업 배포 없음 |

## 2. 기조 (첫 제안)

1. **문제는 정확하게, 무대는 병맛으로.** 문제 내용은 출처와 대조한 사실만 쓰고, 분위기는 밝고 엉뚱하게 가요. 문제 글자만큼은 또렷하고 읽기 쉽게 보여 줘요.
2. **90년대 가족 예능의 레트로 무대.** 진행자 커플, 반짝이 의상 도우미, 손으로 넘기는 점수판, 박수 부대, 브라운관 화면 같은 그 시절 분위기만 살려요. 특정 프로그램의 이름, 코너, 인물, 로고, 화면 구성은 가져오지 않아요.
3. **초2와 어른이 붙어도 접전.** 팀마다 레벨을 고르고, 문제 등급과 핸디캡을 레벨에 맞춰요(6절).
4. **한 판 10분, 바로 한 판 더.** 정규전은 17문제이고, 짧게 하고 싶으면 5분짜리 빠른 판이 있어요.

## 3. 팀 구조

```
           A팀 (왼쪽 단상)          B팀 (오른쪽 단상)
혼자       나              vs       컴퓨터
둘이       1P              vs       2P
```

- 팀은 2명 한 쌍(듀오)이에요. 그림과 동작은 둘을 한 단위로 그리고, 답은 팀이 하나로 해요.
- A팀은 주황 ▲, B팀은 하늘색 ●이에요. 색약이어도 모양으로 구분돼요.
- 둘이 할 때는 기기 하나를 가로로 두고 같이 봐요. 차례인 팀만 답판을 눌러요. 답판 테두리와 단상 조명이 차례 팀 색으로 바뀌어요.

**듀오 (첫 제안 6쌍):** 두 팀이 같은 듀오를 고를 수는 없어요.

| 듀오 | 관계 | 정답일 때 | 틀렸을 때 |
|---|---|---|---|
| 키다리와 꼬마 | 단짝 친구 | 키다리가 꼬마를 번쩍 들어 올려요 | 꼬마가 키다리 다리 뒤로 숨어요 |
| 오빠와 여동생 | 남매 | 여동생이 오빠 등을 팡팡 쳐요 | 둘이 동시에 "너 때문이야!" 하고 서로를 가리켜요 |
| 똑같은 쌍둥이 | 쌍둥이(머리핀 색만 달라요) | 거울처럼 같은 춤을 춰요 | 서로 상대가 틀렸다고 똑같이 우겨요 |
| 반장과 부반장 | 같은 반 | 안경을 동시에 치켜올려요 | 안경에 김이 서려요 |
| 할머니와 손주 | 가족 | 할머니가 엉덩이춤을 춰요 | 손주가 할머니 어깨를 주물러 드려요 |
| 동네 형과 막내 | 이웃 | 하이파이브를 하다 빗나가요 | 형이 막내 머리를 쓰다듬어요 |

## 4. 기회 규칙과 점수 (규칙은 대니님 확정, 점수는 첫 제안)

```
문제 → ① 차례 팀 → 틀리면 ② 상대 팀 → 틀리면 ③ 차례 팀 한 번 더 → 틀리면 ④ 상대 팀 한 번 더 → 정답 공개
         점수 100%          점수 70%            점수 40%                  점수 40%
```

- 차례는 문제마다 A팀, B팀 번갈아 와요.
- 틀린 보기는 회색으로 지운 채 넘겨요. 주관식은 ③부터 초성 힌트를 보여 줘요.
- 4지선다는 보기가 하나만 남으면 맞힌 게 아니라서, 바로 정답을 공개하고 점수는 없어요. 그래서 4지선다는 보통 ③에서 끝나요.
- 시간은 기회마다 4지선다 15초, 주관식 20초예요. 시간이 지나면 틀린 걸로 쳐요.
- 점수는 10점 단위로 반올림해요. 오답 감점은 없어요. 어린 플레이어가 겁먹지 않게요.
- 규칙이 바뀌어도 고치기 쉽게 `logic.js`의 표 하나에 모아요. 대니님이 규칙을 바꾸면 이 표만 고쳐요.

```js
export const TURN_RULE = [
  { who: 'turn',  rate: 1.0 },              // ① 차례 팀
  { who: 'other', rate: 0.7 },              // ② 상대 팀
  { who: 'turn',  rate: 0.4, hint: true },  // ③ 차례 팀 한 번 더(주관식 초성 힌트)
  { who: 'other', rate: 0.4, hint: true },  // ④ 상대 팀 한 번 더
];
```

## 5. 한 판의 흐름 (첫 제안)

### 5.1 정규전 (약 10분, 17문제)

```
오프닝 → 1부 몸풀기 → 2부 분야 판 → 광고 시간 → 3부 역전 한 방 → 시상식
          4지선다 6     섞어서 8      넌센스 2     주관식 1
```

| 순서 | 내용 | 형식 | 점수 |
|---|---|---|---|
| 오프닝 | 브라운관이 켜지고 진행자 커플이 두 팀을 소개해요 | | |
| 1부 몸풀기 | 분야 돌림판이 멈춘 분야로 한 문제씩 내요. 6분야가 한 번씩 나와요 | 4지선다 6문제 | 100 |
| 2부 분야 판 | 6분야 × 2칸(100·200) 패널판에서 차례 팀이 칸을 골라요. 팀마다 4칸 | 100칸 4지선다, 200칸 주관식 | 칸 점수. 한 분야 두 칸을 모두 맞힌 팀은 분야 정복 +100 |
| 광고 시간 | 옛날 TV 광고 패러디(5초, 두 번째부터 건너뛰기) 뒤에 넌센스 | 4지선다 2문제 | 100 |
| 3부 역전 한 방 | 뒤진 팀이 차례예요. 마지막 문제라 점수가 커요 | 주관식 1문제 | 500 |
| 동점이면 | 서든데스. 차례는 돌림판으로 정해요 | 4지선다 1문제 | 맞힌 팀 승리 |
| 시상식 | 트로피와 오늘의 명장면 | | |

- 모든 문제에 4절 기회 규칙을 써요. 점수 칸의 값은 ① 차례 팀이 맞혔을 때 점수예요.
- 2부 패널판은 손으로 넘기는 옛날 패널처럼 보여요. 고른 칸은 맞힌 팀 색으로 뒤집히고, 아무도 못 맞히면 회색이 돼요.
- 문제당 평균 30~40초로 잡아 연출을 넣으면 10분 안팎이에요. 구현 뒤 봇 대전(`tools/sim-match.mjs`)으로 재서 맞춰요.

### 5.2 빠른 판 (약 5분)

짧은 오프닝 → 1부 몸풀기 6문제 → 3부 역전 한 방 → 시상식.

### 5.3 나중에 (M4)

연습 모드(혼자, 분야와 등급을 골라 시간 제한 없이, 해설 자세히)와 오답 노트 다시 풀기.

## 6. 레벨과 핸디캡 (첫 제안)

### 6.1 팀 레벨

| 레벨 | 고르는 이름 | 딱 좋은 문제 |
|---|---|---|
| 1 | 초1~2 | ★1 |
| 2 | 초3~4 | ★2 |
| 3 | 초5~6 | ★3 |
| 4 | 중학생 | ★4 |
| 5 | 어른 | ★5 |

"딱 좋은 문제"는 그 레벨 팀이 **3번에 2번쯤 맞히는** 문제예요. 너무 쉬우면 지루하고, 너무 어려우면 포기해요. 혼자 할 때는 레벨이 판마다 조금씩 움직여요(10.4절 레이팅). 처음 고른 레벨은 출발점이에요.

### 6.2 레벨이 다른 팀끼리

- 문제 등급은 **차례 팀 레벨**에 맞춰요. 넘겨받은 팀은 상대 레벨 문제를 풀게 돼요.
- 2부 분야 판에서 100칸은 차례 팀 레벨 등급의 4지선다, 200칸은 같은 등급이나 한 단계 위의 주관식이에요.
- 3부 역전 한 방은 차례 팀 레벨보다 한 단계 위(★5면 그대로)예요.
- 레벨이 낮은 팀은 시간과 점수를 더 받아요.

| 레벨 차 | 낮은 팀 시간 | 낮은 팀 점수 |
|---|---|---|
| 0 | 같아요 | ×1 |
| 1 | +3초 | ×1.2 |
| 2 | +5초 | ×1.4 |
| 3~4 | +8초 | ×1.6 |

핸디캡 값은 첫 제안이에요. 봇 대전으로 레벨 1 팀과 레벨 5 팀의 승률을 재서 맞춰요.

## 7. 컴퓨터 팀 (혼자 할 때)

대니님 기준은 **컴퓨터가 너무 잘하면 안 된다**예요. 그래서 컴퓨터 실력은 정해진 값이 아니라 플레이어 팀을 따라가요.

| 실력 | 컴퓨터 레이팅 | 느낌 |
|---|---|---|
| 살살 | 플레이어 팀 −200 | 자주 틀려요. 처음 하는 아이에게 |
| 보통(기본) | 플레이어 팀 −80 | 비슷하게 맞히되 조금 덜 맞혀요 |
| 진심 | 플레이어 팀 +40 | 잘하지만 다 맞히지는 않아요 |

- 맞힐 확률은 10.4절과 같은 식으로 정하고, 상한을 0.85로 둬요. 어떤 실력이어도 쉬운 문제를 다 맞히지는 않아요.
- 접전 도우미(기본 켬): 컴퓨터가 300점 넘게 앞서면 레이팅을 100 더 낮추고, 300점 넘게 뒤지면 50 올려요.
- 답하는 데 3~8초 걸려요. 고민하는 동작과 혼잣말("이거 아까 봤는데…")을 보여 주고, 바로 답하지 않아요.
- 4지선다를 틀릴 때는 매력적인 오답(문항의 `lure`)을 더 자주 골라요. 사람이 틀리는 모양과 비슷해져요.
- 목표: 보통 실력에서 플레이어 승률 55~65%. 봇 대전으로 맞춰요.

## 8. 문제 화면과 입력 (첫 제안)

### 8.1 형식

| 형식 | 화면 | 입력 | 맞았는지 보는 법 |
|---|---|---|---|
| 4지선다 | 보기 4개(2×2) | 탭 | 보기 번호 |
| 주관식 · 글자 조각 | 정답 글자와 미끼 글자를 섞은 조각 | 조각을 순서대로 탭, ⌫로 지우기, 확인 | 정규화한 뒤 허용 답과 비교 |
| 주관식 · 숫자 | 숫자 패드 | 탭 | 숫자 일치 |

- **왜 글자 조각인가:** 가로로 든 폰에서는 기기 키보드가 화면 절반을 가리고, 어린 학생은 한글 자판이 느려요. 조각에 미끼를 섞어 보기만 보고 찍기 어렵게 해요. 기기 키보드 입력은 나중에 설정으로 넣을 수 있어요.
- **미끼 글자:** 문항에 적은 `decoys`(헷갈리는 답의 글자, 예: 이순신 → 권·율·신·립)를 먼저 쓰고, 모자라면 같은 분야 다른 답에서 가져와요. 등급이 높을수록 미끼가 많아요(★1은 3개, ★5는 9개).
- **정규화:** 띄어쓰기, 문장부호, 가운뎃점을 지우고 비교해요. 다른 이름이나 호칭이 붙은 답(충무공, 이순신 장군)은 문항의 `accept`에 적힌 것만 정답이에요. 비슷한 답을 자동으로 정답 처리하지 않아요.
- **아까운 답:** 흔한 틀린 이름(예: 직지심경)은 `near`에 적어 두고 "아까워요! 정확한 이름은 ○○예요"를 보여 줘요. 점수는 없고 기회는 넘어가요.

### 8.2 화면 배치

혼자도 둘이도 **가로 화면 하나**로 해요(첫 제안). 무대에 늘 두 팀이 서 있는 그림이라 레이아웃 하나로 둘 다 할 수 있어요.

```
+-------------------------------------------------------------+
| [점수판]  A팀 ▲ 1,250                      B팀 ● 900        |
|       남 진행자    [ 문제 카드        과학 ★2 ]   여 진행자   |
| [A팀 단상]                                      [B팀 단상]  |
| 키다리와 꼬마        >> A팀 차례  15초 <<      오빠와 여동생 |
|                 [ 답판: 보기 2x2 또는 글자 조각 ]            |
+-------------------------------------------------------------+
```

- 세로로 들고 있으면 "가로로 돌려 주세요" 도트 애니메이션을 띄워요. 웹에서는 화면 방향을 잠그지 못하는 브라우저가 있어서 화면이 방향에 맞춰 바뀌어야 해요(구현 전 아이폰 사파리 확인).
- 글자 크기 설정, 시간 제한 끄기(연습·레벨 1), 소리 끄기를 둬요.

## 9. 분야 (첫 제안)

| 분야 | 범위 | 시그니처 문제 | 1차 재료 |
|---|---|---|---|

## 10. 문제은행과 등급

이 게임의 핵심이에요. **문항 하나하나가 출처, 검증 기록, 등급 근거를 가지고 다녀요.**

### 10.1 두 개의 축

| 축 | 묻는 것 | 값 | 정하는 법 |
|---|---|---|---|
| 교과 시점 | 언제 배우나 | 초1~2, 초3~4, 초5~6, 중학, 교과 밖 | NCIC 성취기준 코드로 연결 |
| 등급 | 실제로 얼마나 어렵나 | ★1~★5 | 채점표로 시작하고 플레이 기록으로 보정 |

축을 나누는 이유: 늦게 배워도 쉬운 문제(모나리자를 그린 화가)가 있고, 일찍 배워도 어른이 틀리는 문제(며칠과 몇일)가 있어요. 교과 시점은 범위를 잡는 데 쓰고, 문제를 고를 때는 등급을 써요.

| ★1 | 맹순이도 안다 | 초1~2가 3번에 2번 맞혀요 | 1200 |

독일은 "금속 활자는 구텐베르크가 처음"이라는 흔한 착각을 노린 오답이에요. 한 판에는 같은 사실에서 나온 문제를 하나만 내요. 앞 문제가 뒤 문제의 답을 알려 주지 않게요.

### 10.4 보정 1: 레이팅

문항과 팀이 각각 레이팅을 가져요. 체스 레이팅(Elo)을 교육용 문제 연습에 쓰는 방식이에요(16절 근거).

```
맞힐 확률  p = c + (1 − c) / (1 + 10^((문항 − 팀) / 400))
             c = 1 / 남은 보기 수 (4지선다 찍기),  0 (주관식)
맞히면     문항 −= K × (1 − p),   팀 += K × (1 − p)
틀리면     문항 += K × p,         팀 −= K × p
K          처음엔 크게, 시도가 쌓일수록 작게: K = 64 / (1 + 0.05 × 시도 수)
```

- 처음 문항 레이팅은 등급 중심값(10.2절), 팀 시작값은 레벨에 맞는 등급 중심 +110이에요. 차이가 110이면 주관식을 3번에 2번쯤 맞혀요.
- 레이팅에는 **① 차례 팀의 첫 시도**만 넣어요. 넘겨받은 시도와 한 번 더 시도는 보기가 줄었거나 힌트가 있어서 빼요.
- 컴퓨터 팀의 맞힐 확률도 같은 식을 써요. 넘겨받은 시도에서는 남은 보기 수로 c를 다시 계산해요.
- 문제 고르기: 차례 팀이 맞힐 확률 0.55~0.8인 문항 가운데, 최근에 안 본 것과 분야가 고른 것을 골라요.
- K 값과 찍기 보정 식은 첫 제안이에요. 구현 전에 근거 논문 본문으로 확인해요.

### 10.5 보정 2: 문제은행에 반영

기기 안 레이팅은 그 집 플레이어에게만 맞춰져요. 문제은행 자체의 등급은 이렇게 고쳐요.

```
점검 화면 "기록 내보내기" → JSON(문항 id, 시도·정답 수, 보기별 선택 수, 평균 시간, 주관식 오답 상위 5개, 신고 수)
  → 대니님이 붙여 넣기 → tools/merge-stats.mjs → 문항 stat 갱신과 등급 이동 제안 → 확인 뒤 반영
```

- 등급 이동은 시도 30회 이상이고 추정 정답률이 등급 기준 밖일 때만, 한 번에 한 칸씩, 사람이 확인하고 해요.
- 기록에 이름이나 팀 이름 같은 개인 정보는 넣지 않아요.

**이상 신호 → 점검 대기열**

| 신호 | 의심 |
|---|---|
| 레벨 높은 팀이 오히려 더 틀려요 | 문제가 모호하거나 정답이 틀렸어요 |
| 오답 하나에 40% 넘게 몰려요 | 정답 오류, 또는 함정이 너무 세요 |
| 주관식에서 같은 오답이 반복돼요 | 허용 답 누락(예: '충무공') |
| "이 문제 이상해요" 신고 | 해설 화면의 신고 버튼 |

### 10.6 출제 원칙 (고퀄 기준)

1. **정답은 하나.** 뜻이 갈리는 말은 풀어 써요(아래 금성 사례).
2. **바뀌는 사실은 피해요.** 인구, 기록, 순위는 꼭 필요할 때만 기준 연도를 쓰고 `valid`(유효 기한)를 달아요.
3. **오답 보기는 흔한 착각에서.** 같은 종류, 비슷한 길이로 써요. "모두 정답", "정답 없음"은 쓰지 않아요.
4. **"아닌 것은?"은 분야마다 10% 이하.** 쓰면 '아닌'을 굵게 표시해요.
5. **짧게.** 문제는 ★1~2는 40자, ★3~5는 60자 안이에요. 가로 화면에서 두 줄을 넘지 않아요.
6. **해설은 필수.** 왜 정답인지 한두 문장, 가장 그럴듯한 오답이 왜 틀렸는지 한 문장.
7. **원문을 옮기지 않아요.** 출처에서 사실만 가져와 새 문장으로 써요(10.8절).
8. **말투.** 문제와 해설은 해요체예요. '합니다'체는 쓰지 않아요. 진행자 대사만 90년대 방송 말투를 흉내 내요(11.2절).
9. **피하는 주제.** 정치 현안, 종교 교리, 특정 인물·지역·외모를 깎아내리는 개그, 차별. 근현대사는 교과서 서술 범위의 사실만 다뤄요.
10. **넌센스는 근거를 써요.** 해설에 말장난이 어디서 나오는지 쓰고, 그럴듯한 다른 답이 있으면 `accept`에 넣거나 버려요. 오답 보기도 웃기게 써요. 예: "깨뜨릴수록 칭찬받는 것은? ① 접시 ② 기록 ③ 유리창 ④ 약속" → 해설 "약속을 깨면 혼나요."
11. **한 판에 같은 사실은 한 번.** 사실 카드 id가 같은 문항은 한 판에 하나만 나와요.

**사례: 정답이 둘이 될 뻔한 문제**

- 처음 쓴 문제: "하루가 1년보다 긴 행성은?" (정답 금성)
- 걸린 점: '하루'를 스스로 한 바퀴 도는 시간(자전 주기)으로 보면 금성(약 243일)이 1년(약 225일)보다 길어서 맞아요. 그런데 해가 떴다가 다시 뜰 때까지(태양일)로 보면 금성은 약 117일이라 1년보다 짧고, 오히려 수성(태양일 약 176일, 1년 약 88일)이 맞아요.
- 고친 문제: "태양계 행성 가운데 스스로 한 바퀴 도는 시간(자전 주기)이 태양을 한 바퀴 도는 시간(공전 주기)보다 긴 행성은? ① 수성 ② 금성 ③ 화성 ④ 목성" (★5, 채점 3·2·2·1)
- 수성은 이 함정을 아는 사람을 흔드는 오답으로 남겼어요.

### 10.7 만드는 순서

```
① 범위표      NCIC 성취기준 → 분야·교과 시점별 주제 목록
② 사실 카드   허용된 출처에서 사실 한 줄 + 출처 id + 확인일
③ 문항 쓰기   사실 카드 → 형식·등급별 문항 1~3개 + 해설 + 오답 근거 + 채점표
④ 자동 검사   tools/check-bank.mjs: 형식, 중복·유사 문항, 길이, 말투, 금지어, 출처, 허용 답, 채점표 합계와 등급
⑤ 사실 검증   출제자와 다른 검증자가 출처와 대조: 정답이 하나인지, 모호하지 않은지
⑥ 대니님 검수 묶음마다 무작위 10문항 이상
⑦ 출시·보정   10.4~10.5절
```

- 상태: `draft` → `checked`(⑤ 통과) → `live`(⑥ 통과) → `flagged`(이상 신호) → `retired`
- 문항 쓰기와 검증은 Claude Code가 해요(구독 범위, 유료 API 호출 없음). 검증자는 출제자의 메모를 보지 않는 별도 에이전트예요.
- 많이 만들 때도 묶음(분야 하나 × 30문항)마다 ④~⑥을 거쳐요.

## 11. 무대와 캐릭터 (분위기는 대니님 확정, 세부는 첫 제안)

### 11.1 레트로 무대

- 90년대 방송국 공개홀이에요. 반짝이 커튼, 원형 조명, 손으로 넘기는 숫자 점수판, 박수 치는 방청석이 있어요.
- 화면은 살짝 둥근 브라운관 느낌이에요. 설정에서 끌 수 있어요.
- 자막은 그 시절 예능 자막처럼 두꺼운 외곽선에 통통 튀는 글자예요.
- 장면이 바뀔 때 브라운관이 지지직거리고, "잠시 후 계속됩니다" 화면이 나와요.
- 특정 프로그램의 이름, 코너, 인물, 로고, 화면 구성은 쓰지 않아요. 그 시절 분위기만 가져와요.

### 11.2 출연진

| 이름 | 역할 | 모습과 버릇 |
|---|---|---|
| 왕대박 | 남자 진행자 | 2:8 가르마, 커다란 나비넥타이, 어깨가 각진 양복. 뭐든 "대~박!"으로 부풀려요. 문제 카드를 자주 거꾸로 들어요 |
| 나정답 | 여자 진행자 | 단정한 단발에 또박또박 진행해요. 허둥대는 왕대박을 수습하고, 정답 공개는 늘 이 사람이 해요 |
| 반짝이 | 도우미 | 반짝이 조끼에 롤러스케이트. 문제 봉투와 정답판을 들고 무대를 가로질러요. 가끔 미끄러져요 |
| 넘김 아저씨 | 점수판 담당 | 숫자판을 손으로 넘겨요. 가끔 거꾸로 걸어서 6이 9가 돼요 |
| 짝짝 반장 | 방청석 박수 반장 | "박수!", "웃음!", "아~" 피켓을 번쩍 들어요 |
| 물음이 | 물음표 탈인형 | 광고 시간과 시상식에서 엉성하게 춤춰요 |

- 진행자 대사는 90년대 방송 말투를 흉내 내요. 예: "정답~ 입니다~!", "자, 운명의 패널을 골라 주세요!" 진행자 둘만 '합니다'체를 써요. 문제, 해설, 버튼과 안내는 해요체예요.
- M1에는 진행자 커플과 반짝이만 넣고, 나머지는 M2에서 넣어요.

### 11.3 병맛 연출

- 정답: 반짝이가 종을 치고 꽃가루가 날려요. 듀오는 정답 동작을 하고, 넘김 아저씨가 점수판을 넘겨요.
- 오답: 천장에서 고무 닭이 "꽥" 하고 떨어져요. 듀오는 오답 동작을 하고, 방청석이 "아~" 해요.
- ★5 정답: 왕대박의 나비넥타이가 빙글빙글 돌며 날아가요. "천재 등장" 자막이 떠요.
- 광고 시간: 옛날 TV 광고 패러디예요. 실제 상표는 쓰지 않아요. 과장 광고를 비꼬는 내용이라, 웃기면서 "광고를 그대로 믿지 말자"는 덤도 있어요.
  - 1초 천재 알약: "먹으면 천재! (※ 효과 없음)"
  - 공부가 저절로 되는 베개: "자는 동안 100점! (※ 꿈에서만)"
  - 만능 지우개: "틀린 답도 싹! (※ 시험지는 안 돼요)"
- 시상식: 1등 팀은 너무 커서 비틀거리게 되는 금 트로피, 진 팀은 "다음엔 이긴다" 리본을 받아요. 그 판에서 가장 어려운 문제를 맞힌 순간을 "오늘의 명장면"으로 다시 보여 줘요.
- 피하는 것: 더럽거나 냄새나는 개그, 때리는 연출, 외모 놀림.

### 11.4 세련된 도트

| | 세련 | 병맛 |
|---|---|---|
| 어디에 | 화면 구조, 글자, 색, 움직임 | 내용, 대사, 연출 |
| 어떻게 | 고정 팔레트 32색, 정수배 확대, 픽셀 격자에 맞춘 부드러운 움직임, 넉넉한 여백 | 과장된 리액션, 예능 자막 패러디, 가짜 광고, 진행자 콩트 |

- 해상도: 480×270 화면에 그리고 정수배로 키워요. 좀비 아웃포스트 `title.js`의 픽셀 버퍼·팔레트·디더링 방식을 그대로 가져와요.
- 글자: 문제, 보기, 해설은 DOM 글자로 또렷하게 보여 줘요. 도트 글꼴 갈무리(Galmuri, OFL 1.1)를 쓰고, 설정에서 "읽기 편한 글꼴"로 바꿀 수 있어요.
- 그림 만드는 법: 1차는 코드로 그리는 도트(픽셀 배열 + 팔레트)예요. 또렷하고, 용량이 작고, 팔레트가 맞고, 라이선스 걱정이 없어요. M1에서 듀오 하나와 진행자 커플, 무대를 먼저 그려 대니님이 보고, 품질이 모자라면 agent-bridge `asset_gen` 의뢰(이미지 모델 시안 → 32색 격자 정리)로 바꿔요.
- 도트 이펙트는 M1에서 COREVIS Library 후보를 확인해요(카페 때는 화풍이 맞지 않아 기각했어요).

### 11.5 소리

- 효과음은 Web Audio로 합성해요(저장소 방식): 정답 딩동댕, 오답 땡, 째깍, 고무 닭 꽥, 박수, 탄식, 패널 넘기는 소리.
- 배경음악은 M1에서 합성 칩튠 루프로 시작하고, M3에서 Suno로 오프닝 곡, 라운드별 곡, 광고 징글, 시상식 곡을 만들어요(agent-bridge 의뢰, `docs/bgm-style.md` 방식). 방향은 90년대 예능 밴드 사운드(신스 브라스, 슬랩 베이스)예요.
- 문제 읽어 주기(M3, 선택): 레벨 1에서 브라우저 음성 합성(ko-KR)으로 문제를 읽어 줘요. 기기마다 목소리가 달라서 구현 전에 확인해요.

## 16. 선행조사 기록

- **채택 — 문항과 플레이어를 함께 매기는 레이팅(Elo 변형):** Pelánek, "Applications of the Elo rating system in adaptive educational systems", Computers & Education, 2016 ([논문 정보](https://is.muni.cz/publication/1376317), [PDF](https://www.fi.muni.cz/~xpelanek/publications/CAE-elo.pdf)). 사실 암기 연습에 쓴 사례도 있어요([EDM 2014](https://www.fi.muni.cz/~xpelanek/publications/EDM14-adaptive-facts.pdf)). 지금은 초록과 요약만 봤어요. 구현 전에 본문으로 K 값과 찍기 보정 식을 확인해요.
- **채택 — 도트 글꼴 갈무리:** SIL OFL 1.1, npm `galmuri`. 글꼴만 따로 팔지 않으면 게임과 함께 배포할 수 있어요([GitHub](https://github.com/Quiple/Galmuri), [README](https://cdn.jsdelivr.net/npm/galmuri@2.40.3/README.md)).
- **기각 — 주관식 기본 입력을 기기 키보드로:** 가로로 든 폰에서는 키보드가 화면 절반을 가리고, 어린 학생은 한글 자판이 느려요. 글자 조각을 기본으로 해요. 나무위키는 검증 안 된 서술 때문에 재료에서 뺐어요.
- **주의 — Elo 추정의 한계:** 치우칠 수 있고 맥락에 따라 흔들린다는 연구가 있어요([Keeping Elo alive, 2025](https://research.tilburguniversity.edu/en/publications/keeping-elo-alive-evaluating-and-improving-measurement-properties/)). 그래서 문제은행 등급 이동은 시도 30회 이상, 한 칸씩, 사람 확인으로 묶었어요.
- **주의 — 제목 겹침:** 넥슨 '큐플레이(구 퀴즈퀴즈)'와 웹 버전 '퀴즈퀴즈R' 기사([게임메카](https://www.gamemeca.com/view.php?gid=89218)). 대니님이 알고 정했어요.
- **구현 전 확인:** 갈무리 woff2 용량과 한글 글자 수, 아이폰 사파리의 화면 방향 잠금, 브라우저 음성 합성 ko-KR 목소리, Natural Earth 이용 조건, COREVIS 도트 이펙트 후보.
